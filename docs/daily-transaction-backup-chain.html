DAILY-TransactionBackup 배치 체인 분석

Control-M 폴더 정의 기반 일일 거래 백업 배치 체인 — CardDemo 메인프레임 애플리케이션

FOLDER_NAME = DAILY-TransactionBackup APPLICATION = CARD-DEMO SUB_APPLICATION = CTRLM 작업 4개

출처: app/scheduler/CardDemo.controlm (3–25행), app/jcl/CLOSEFIL.jcl, app/jcl/TRANBKP.jcl, app/jcl/WAITSTEP.jcl, app/jcl/OPENFIL.jcl, app/proc/REPROC.prc, app/cbl/COBSWAIT.cbl, README.md

1. 체인 개요 — 처리 패턴

이 체인은 온라인(CICS)에서 사용 중인 파일을 닫고 → 거래 파일을 백업하고 → 잠시 대기한 뒤 → 다시 CICS에 파일을 열어주는 전형적인 메인프레임 일일 백업 패턴입니다. CICS 리전(CICSAWSA)이 VSAM 파일을 열어 둔 상태에서는 배치 작업이 해당 파일을 안전하게 복사·삭제·재정의할 수 없기 때문에, 백업 전후로 파일을 닫고 여는 단계가 반드시 필요합니다.

① CICS 파일 닫기CLOSEFIL — 온라인 접근 차단
② 거래 백업TRANBKP — 거래 마스터를 GDG로 복사 후 재생성
③ 대기WAITSTEP — 지정 시간(36초) 대기
④ CICS 파일 다시 열기OPENFIL — 온라인 서비스 재개

2. 체인 흐름도

화살표 = 선행 작업이 정상 종료되면 OUTCOND(+)를 추가하고, 후속 작업은 해당 조건을 INCOND로 기다립니다. 모든 조건은 ODATE="ODAT"(같은 주문일) 기준입니다.

4. 의존성 조건 (INCOND / OUTCOND)

순서작업INCOND (선행 조건 대기)OUTCOND (조건 추가 + / 삭제 −)ODATEAND_OR

(추가 조건 없음 — 체인 종료)		ODATA
  • ODATE="ODAT": 조건은 작업이 주문된 날짜(Order Date)로 생성·확인됩니다. 따라서 같은 날 주문된 체인 안에서만 조건이 연결되며, 전날 남은 조건으로 오늘 작업이 실행되지 않습니다.
  • AND_OR="A": INCOND를 AND로 결합합니다. 각 작업의 INCOND가 하나뿐이므로 실질적으로 “선행 작업 조건이 존재해야 실행”을 의미합니다.
  • SIGN="+"/"−": 작업이 정상 종료되면 다음 작업용 조건을 추가(+)하고, 자신이 소비한 입력 조건은 삭제(−)해서 같은 조건으로 재실행되는 것을 막습니다. 마지막 OPENFIL은 입력 조건만 삭제하여 체인을 정리합니다.

6. 분석 시 참고 사항

README와 JCL의 차이 — README의 애플리케이션 상세 표는 CLOSEFIL/OPENFIL의 프로그램을 IEFBR14로 적고 있지만, 실제 JCL은 PGM=SDSF로 CEMT 명령을 CICS 리전 CICSAWSA에 보냅니다. 이 문서는 JCL을 기준으로 작성했습니다.
TRANBKP 삭제 단계에 COND 없음 — STEP05(DELETE)에는 COND가 없어, REPRO(STEP05R)가 비정상 종료(abend)가 아닌 오류 코드로 끝나도 거래 KSDS가 삭제됩니다. 또한 AIX(TRANSACT.VSAM.AIX)는 삭제되지만 이 작업에서 다시 만들지 않으며, AIX 재생성은 별도 TRANIDX.jcl에서만 수행됩니다.
CA-7 정의와의 차이 — app/scheduler/CardDemo.ca7의 일일 체인(SCHID=030)은 CLOSEFIL → CBPAUP0J → POSTTRAN → WAITSTEP → OPENFIL로, TRANBKP가 포함되어 있지 않습니다. 이 문서는 Control-M 정의(CardDemo.controlm)만 다룹니다.
