1. Business Flow Analysis

1.1 Business Context

The Account Update transaction (CAUP) provides customer service representatives with the ability to modify account master data and associated customer demographic information for a given credit card account. The operator enters an 11-digit account number; the system retrieves and displays the current account details (balances, limits, dates) together with the linked customer record (name, address, phone, SSN, FICO score). The operator makes changes and the system validates all fields before persisting updates to both the ACCTDAT and CUSTDAT VSAM files in a single logical unit of work.

This is the largest online program in CardDemo (4,236 LOC) due to its comprehensive field-level validation of over 30 editable fields spanning account financial data and customer demographics.

7.3 Conversation State Management

State is preserved between pseudo-conversational iterations via the combined COMMAREA (CARDDEMO-COMMAREA + WS-THIS-PROGCOMMAREA) passed on EXEC CICS RETURN TRANSID('CAUP') COMMAREA(WS-COMMAREA). The total COMMAREA is defined as WS-COMMAREA PIC X(2000). On re-entry, the program splits DFHCOMMAREA back into the two structures using offset arithmetic based on LENGTH OF CARDDEMO-COMMAREA.

9. Security and Authorization

9.1 Transaction Security

The CAUP transaction is accessible to regular users (CDEMO-USRTYP-USER = 'U') via the Main Menu (CM00). Access control is enforced at the menu level by COSGN00C which routes users to the appropriate menu based on their user type. COACTUPC itself does not perform an explicit security check — it relies on the sign-on (CC00) having authenticated the user and the menu (CM00) only presenting this option to authorized users.

On exit (PF03), the program explicitly sets SET CDEMO-USRTYP-USER TO TRUE, preserving the user type in the COMMAREA for downstream programs.

9.2 Data Access Authorization

No data-level authorization checks are performed within this program. Any user who can reach the CAUP transaction can update any account by entering its 11-digit account number. In a production CICS environment, RACF/ACF2 resource-level security on the FCT entries (ACCTDAT, CUSTDAT, CXACAIX) would restrict file access at the infrastructure level.

9.3 Audit Trail

The program does not explicitly write audit records. Changes are persisted directly to the VSAM files without a separate audit log. In a modernized environment, this would be a candidate for adding audit trail functionality (change history with user ID, timestamp, before/after values).
