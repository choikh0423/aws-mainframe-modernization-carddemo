Business Flow Analysis

1.1 Business Context

The Transaction List screen is the primary entry point for browsing credit-card transactions within the CardDemo application. It is accessible from the Main Menu (option 6 — program COTRN00C) by both regular users and administrators.

The transaction allows an operator to:

  • View a paginated list of transactions from the TRANSACT VSAM KSDS file, displaying 10 records per page.
  • Search for transactions by entering a numeric Transaction ID as a starting key.
  • Navigate forward (PF8) and backward (PF7) through pages of results.
  • Select a specific transaction (by typing ‘S’ in the selection field) to transfer control to the Transaction View screen (COTRN01C).

The business outcome is a fast, interactive lookup capability enabling operators to locate and drill into individual transaction records for review or audit.

7.2 Return Code Conventions

The program uses WS-RESP-CD (PIC S9(09) COMP) to capture CICS RESP codes from file operations. Response values are evaluated against DFHRESP(NORMAL), DFHRESP(NOTFND), DFHRESP(ENDFILE), and a catch-all OTHER condition. No application-level return codes are passed to calling programs.

7.3 Conversation State Management

State is preserved across pseudo-conversational iterations via the CARDDEMO-COMMAREA passed on EXEC CICS RETURN TRANSID('CT00') COMMAREA(CARDDEMO-COMMAREA).

Key state elements maintained between iterations:

  • CDEMO-PGM-CONTEXT — 0 on first entry, set to 1 (CDEMO-PGM-REENTER) after initial display. Controls whether the program performs the first-time browse or processes user input.
  • CDEMO-CT00-TRNID-FIRST / CDEMO-CT00-TRNID-LAST — Anchor keys for the current page boundaries. Used to position the browse cursor for PF7 (backward) and PF8 (forward) navigation.
  • CDEMO-CT00-PAGE-NUM — Current page counter displayed on screen and used to prevent backward navigation past page 1.
  • CDEMO-CT00-NEXT-PAGE-FLG — ‘Y’/‘N’ flag set by the look-ahead READNEXT that determines whether PF8 should allow forward pagination.

Security and Authorization

9.1 Transaction Security

Access to the CT00 transaction is controlled through the CardDemo application’s menu routing system:

  • The program checks EIBCALEN = 0 at entry (line 107). If no COMMAREA is present (indicating the user did not arrive via the authenticated menu flow), the program redirects to COSGN00C (Sign-On), effectively preventing unauthorized direct invocation.
  • In the menu definition (COMEN02Y.cpy), Transaction List (option 6 → COTRN00C) is flagged as user-type ‘U’, meaning it is accessible to both regular users and administrators.

10.2 Performance Considerations

  • Browse operation overhead: Each page navigation opens a new browse session (STARTBR), reads the required records, and immediately closes it (ENDBR). This is the standard pseudo-conversational pattern but means the VSAM index is re-traversed on every page turn.
  • Look-ahead read: After populating 10 rows, the program performs one additional READNEXT to determine if more pages exist (setting NEXT-PAGE-YES/NO). This is efficient (single extra I/O) but slightly increases per-page cost.
  • Skip read on non-Enter keys: For PF7/PF8, the program performs one extra READNEXT/READPREV before the main loop to skip past the current boundary record, avoiding duplicate display of the last/first record.
  • No index caching: Page position is maintained via COMMAREA keys (CDEMO-CT00-TRNID-FIRST, CDEMO-CT00-TRNID-LAST) rather than VSAM RBAs, which is portable but may be slower on very large files.
  • Low memory footprint: Only one TRAN-RECORD (350 bytes) is in memory at a time during the browse loop; the 10 display rows are populated directly into the BMS map fields.
