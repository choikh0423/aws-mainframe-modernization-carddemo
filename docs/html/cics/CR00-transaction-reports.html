Business Flow Analysis

▾

1.1 Business Context

The Transaction Reports function allows authorized users to request printed transaction reports covering a selectable date range. The user chooses one of three report types—Monthly (current month), Yearly (current year), or Custom (user-specified date range)—and confirms the submission. The program then assembles JCL for the TRNRPT00 batch job and writes it line-by-line to the JOBS extra-partition Transient Data Queue (TDQ), which routes the JCL to the internal reader for batch execution.

Users: Regular and admin users (menu option 9 on the main menu).
Trigger: User selects “Transaction Reports” from the main menu (program COMEN01C).
Business Outcome: A batch report job is submitted to the JES internal reader, producing a printed transaction report filtered by the requested date range.

5.1 File Inventory

N/A — CORPT00C does not perform any direct VSAM file operations (no READ, WRITE, REWRITE, DELETE, STARTBR, or READNEXT commands). All data access is deferred to the batch job (TRNRPT00) submitted via the TDQ.

Working storage does define WS-TRANSACT-FILE PIC X(08) VALUE 'TRANSACT', but this file is not accessed by the online program. The batch job TRNRPT00 (invoked via JCL PROC TRANREPT) reads the TRANSACT file.

7.3 Conversation State Management

State is managed through the standard CardDemo COMMAREA (CARDDEMO-COMMAREA) passed on each RETURN TRANSID('CR00'). The key state indicator is CDEMO-PGM-CONTEXT:

  • 0 (CDEMO-PGM-ENTER) — First entry into the program; screen is initialized and sent with ERASE.
  • 1 (CDEMO-PGM-REENTER) — Subsequent entries; user input is received and processed.

No screen-level state is preserved in the COMMAREA between iterations. All report selection and date data resides in the BMS map buffers (CORPT0AI/CORPT0AO) which are re-received each iteration. After successful submission, INITIALIZE-ALL-FIELDS clears all input fields.

Security and Authorization

▾

9.1 Transaction Security

Access to CR00 is controlled at two levels:

  • CICS Transaction Security: The transaction CR00 can be protected via RACF transaction-level security in the CICS region definition.
  • Application-Level Routing: The main menu program (COMEN01C) routes to CORPT00C as menu option 9. The menu is available to both regular users (CDEMO-USER-TYPE = 'U') and admin users ('A').
  • EIBCALEN Check: If EIBCALEN = 0 (no COMMAREA, indicating the user has not passed through the sign-on flow), the program immediately transfers control to COSGN00C (sign-on program), preventing unauthenticated access.

9.2 Data Access Authorization

CORPT00C does not access any VSAM files directly. The TDQ “JOBS” is an extra-partition queue whose access is controlled by the CICS TDQ definition and the underlying JES security. The batch job (TRNRPT00) runs under the submitting user’s authority as specified by NOTIFY=&SYSUID in the JCL.

9.3 Audit Trail

No explicit audit logging is performed by CORPT00C. The only diagnostic output is a DISPLAY statement that writes RESP and REAS codes to SYSOUT when the WRITEQ TD command fails. The JES job submission itself creates an audit trail through the JES job log (JESMSGLG, JESJCL, JESYSMSG).
