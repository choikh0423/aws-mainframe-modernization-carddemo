Business Flow Analysis

1.1 Business Context

  • What: Refreshes the Disclosure Group VSAM KSDS file (DISCGRP.VSAM.KSDS) from a flat-file source (DISCGRP.PS). The process closes CICS files to release VSAM locks, deletes the existing VSAM cluster, redefines it, repopulates from the flat file, pauses to allow propagation, and reopens the CICS files.
  • Who: Downstream consumers include the Monthly Interest Calculation batch (INTCALC/CBACT04C) which uses disclosure group interest rates to calculate account-level interest charges, and the CICS online system which references disclosure groups during transaction authorization.
  • When: Runs weekly on Saturday, after the MNTTRDB2 (Transaction Types DB Refresh) job completes. Scheduled via Control-M in the WEEKLY-DisclosureGroupsRefresh SMART folder.
  • Why: Disclosure groups define the interest rates applicable to each combination of account group, transaction type, and transaction category. Periodic refresh ensures that rate changes from the source-of-truth flat file (maintained by product management) are propagated to the VSAM file consumed by online and batch processes.
  • Outcome: A freshly rebuilt DISCGRP.VSAM.KSDS containing all current disclosure group records with up-to-date interest rates. CICS files are reopened and the online system resumes with the refreshed data.

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  JOB 1: CLOSEFIL
    STEP: CLCIFIL  EXEC PGM=SDSF
      INPUT: ISFIN DD * (inline CEMT commands)
      PROCESSING:
        1. /F CICSAWSA,'CEMT SET FIL(TRANSACT ) CLO'
        2. /F CICSAWSA,'CEMT SET FIL(CCXREF ) CLO'
        3. /F CICSAWSA,'CEMT SET FIL(ACCTDAT ) CLO'
        4. /F CICSAWSA,'CEMT SET FIL(CXACAIX ) CLO'
        5. /F CICSAWSA,'CEMT SET FIL(USRSEC ) CLO'
      OUTPUT: ISFOUT, CMDOUT (SYSOUT=* spool)

  JOB 2: DISCGRP
    STEP05: EXEC PGM=IDCAMS
      INPUT: SYSIN DD * (inline)
      PROCESSING:
        1. DELETE AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS CLUSTER
        2. SET MAXCC = 0  (tolerate "not found" on first run)
      RC: 0 (always, due to SET MAXCC)

    STEP10: EXEC PGM=IDCAMS
      INPUT: SYSIN DD * (inline)
      PROCESSING:
        1. DEFINE CLUSTER (NAME(AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS))
           - CYLINDERS(1 5)
           - VOLUMES(AWSHJ1)
           - KEYS(16 0)         [16-byte key at offset 0]
           - RECORDSIZE(50 50)  [fixed-length 50 bytes]
           - SHAREOPTIONS(2 3)
           - ERASE, INDEXED
           - DATA  (NAME(...KSDS.DATA))
           - INDEX (NAME(...KSDS.INDEX))
      RC: 0=success, 12=DEFINE failed

    STEP15: EXEC PGM=IDCAMS
      INPUT:
        - DISCGRP DD DSN=AWS.M2.CARDDEMO.DISCGRP.PS  (flat file)
        - DISCVSAM DD DSN=AWS.M2.CARDDEMO.DISCGRP.VSAM.KSDS  (VSAM)
      PROCESSING:
        1. REPRO INFILE(DISCGRP) OUTFILE(DISCVSAM)
      RC: 0=all records loaded, 4+=partial/error

  JOB 3: WAITSTEP
    STEP: WAIT  EXEC PGM=COBSWAIT
      INPUT: SYSIN DD * (inline: "00003600")
      STEPLIB: AWS.M2.CARDDEMO.LOADLIB
      PROCESSING:
        1. ACCEPT PARM-VALUE FROM SYSIN  ("00003600")
        2. MOVE PARM-VALUE TO MVSWAIT-TIME
        3. CALL 'MVSWAIT' USING MVSWAIT-TIME
           (Wait 3600 centiseconds = 36 seconds)
        4. STOP RUN
      RC: 0

  JOB 4: OPENFIL
    STEP: OPCIFIL  EXEC PGM=SDSF
      INPUT: ISFIN DD * (inline CEMT commands)
      PROCESSING:
        1. /F CICSAWSA,'CEMT SET FIL(TRANSACT ) OPE'
        2. /F CICSAWSA,'CEMT SET FIL(CCXREF ) OPE'
        3. /F CICSAWSA,'CEMT SET FIL(ACCTDAT ) OPE'
        4. /F CICSAWSA,'CEMT SET FIL(CXACAIX ) OPE'
        5. /F CICSAWSA,'CEMT SET FIL(USRSEC ) OPE'
      OUTPUT: ISFOUT, CMDOUT (SYSOUT=* spool)

Checkpoint, Restart, and Recovery

8.1 Checkpoint Strategy

Warning: This job stream does not implement application-level checkpointing. The DELETE/DEFINE/REPRO pattern in DISCGRP is inherently atomic at the step level: each IDCAMS step either completes fully or fails. However, a failure between steps (e.g., after DELETE but before DEFINE completes) leaves the VSAM cluster in an undefined state.

9.4 COBSWAIT Error Handling

The COBSWAIT program contains no explicit error handling. There are no file I/O status checks, no ON ERROR clauses, and no CALL to CEE3ABD. If the ACCEPT from SYSIN fails or the CALL 'MVSWAIT' fails, the program will ABEND with a system completion code.

  • If SYSIN is missing: S013 (DD not found) or data exception
  • If PARM-VALUE is non-numeric: S0C7 (data exception on MOVE to COMP field)
  • If MVSWAIT is unavailable: S806 (module not found)

Performance and Batch Window Analysis

11.1 Performance Characteristics

This job stream is lightweight. The primary I/O is the IDCAMS REPRO step which loads approximately 51 records (50 bytes each, ~2.5 KB total) into a VSAM KSDS. Key performance observations:

  1. CLOSEFIL/OPENFIL: Near-instant execution. SDSF issues CICS CEMT commands via /F; response time depends on CICS region responsiveness (typically sub-second per command).
  2. DISCGRP STEP05 (DELETE): Sub-second. Single catalog operation to remove a small VSAM cluster.
  3. DISCGRP STEP10 (DEFINE): Sub-second. Catalog-only operation to define a new cluster with CYLINDERS(1 5).
  4. DISCGRP STEP15 (REPRO): Sub-second for 51 records. Sequential read of flat file + keyed VSAM writes. I/O count: 51 reads + 51 writes.
  5. WAITSTEP: Fixed 36-second pause. This is the longest step in the stream by design.
Performance note: The 36-second WAITSTEP dominates the total elapsed time. For small disclosure group datasets (current: 51 records), the CLOSEFIL + DISCGRP + OPENFIL steps complete in under 5 seconds. Total stream elapsed time is approximately 42 seconds.
