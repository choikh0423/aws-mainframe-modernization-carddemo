Business Flow Analysis

1.1 Business Context

  • What: Generates per-card account statements in two formats (plain-text PS and HTML) by reading all posted transactions from a sorted VSAM copy, enriching them with customer demographics and account details, and producing formatted output suitable for printing or web delivery.
  • Who: Downstream consumers include statement distribution (print/mail), customer self-service portals (HTML format), and audit/compliance review teams.
  • When: Runs on-demand after the Daily Transaction Posting job (POSTTRAN/CBTRN02C) has populated the Transaction Master VSAM with the current period’s transactions.
  • Why: Regulatory and customer-service requirement—cardholders must receive periodic statements showing all transactions, balances, and account identification.
  • Outcome: Two output files produced: STATEMNT.PS (plain-text, 80-byte LRECL) and STATEMNT.HTML (HTML table format, 100-byte LRECL), each containing one statement block per card number found in the Cross-Reference file.

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  STEP040 - EXEC PGM=CBSTM03A (CALL CBSTM03B for all file I/O)
    INPUTS (via CBSTM03B):
      - TRNXFILE: AWS.M2.CARDDEMO.TRXFL.VSAM.KSDS      (indexed sequential read)
      - XREFFILE: AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS    (indexed sequential read)
      - CUSTFILE: AWS.M2.CARDDEMO.CUSTDATA.VSAM.KSDS    (indexed random read)
      - ACCTFILE: AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS    (indexed random read)
    OUTPUTS (direct WRITE in CBSTM03A):
      - STMTFILE: AWS.M2.CARDDEMO.STATEMNT.PS           (sequential output)
      - HTMLFILE: AWS.M2.CARDDEMO.STATEMNT.HTML          (sequential output)

    PROCESSING:
      1. Access PSA → TCB → TIOT control blocks; display job/step/DD info
      2. OPEN OUTPUT STMT-FILE, HTML-FILE
      3. Open TRNXFILE via CBSTM03B (ALTER jump to 8100-TRNXFILE-OPEN)
         a. Read first record, save card number
         b. 8500-READTRNX-READ: Load ALL transactions into WS-TRNX-TABLE
            (2D array: 51 cards × 10 transactions each)
            Loop until EOF on TRNXFILE; group by card number
      4. Open XREFFILE via CBSTM03B (ALTER jump to 8200-XREFFILE-OPEN)
      5. Open CUSTFILE via CBSTM03B (ALTER jump to 8300-CUSTFILE-OPEN)
      6. Open ACCTFILE via CBSTM03B (ALTER jump to 8400-ACCTFILE-OPEN)
      7. 1000-MAINLINE: PERFORM UNTIL END-OF-FILE = 'Y'
         a. 1000-XREFFILE-GET-NEXT: Read next XREF record (sequential)
         b. 2000-CUSTFILE-GET: READ CUSTFILE by XREF-CUST-ID (random)
         c. 3000-ACCTFILE-GET: READ ACCTFILE by XREF-ACCT-ID (random)
         d. 5000-CREATE-STATEMENT: Write header (name, address, acct, bal, FICO)
            - Plain-text: ST-LINE0 through ST-LINE13
            - HTML: Full HTML document header with table structure
         e. 4000-TRNXFILE-GET: Match card in WS-TRNX-TABLE
            - For each matching transaction:
              6000-WRITE-TRANS: Write tran ID, description, amount
            - Accumulate WS-TOTAL-AMT
            - Write footer (total + end-of-statement marker)
      8. Close all files (TRNXFILE, XREFFILE, CUSTFILE, ACCTFILE, STMT, HTML)
      9. GOBACK

    RC: 0 = Success (no explicit RC setting; ABEND on any I/O error)

3.3 GDG Usage

Not applicable. CREASTMT does not use Generation Data Groups. Output files (STATEMNT.PS, STATEMNT.HTML) are simple catalogued datasets that are deleted and recreated each run.

3.4 Scheduler Dependencies

Note: CREASTMT is not in the Control-M schedule (app/scheduler/CardDemo.controlm). It is an on-demand job triggered manually after POSTTRAN has populated the Transaction Master with current-cycle data. It must run after POSTTRAN completes and the TRANSACT VSAM contains the transactions to be reported. 
  POSTTRAN (post daily transactions)
       │
       ▼
  CREASTMT (on-demand, triggered by operations)
       │
       ├── DELDEF01: Define temp TRXFL cluster
       ├── STEP010:  SORT TRANSACT → TRXFL.SEQ (by card#)
       ├── STEP020:  REPRO → TRXFL VSAM
       ├── STEP030:  Delete old outputs
       └── STEP040:  Generate statements
                │
                ▼
         STATEMNT.PS + STATEMNT.HTML → Distribution

9.4 File Status Code Handling

CBSTM03B returns file status in LK-M03B-RC (2 bytes). CBSTM03A checks this after every CALL:

  • '00' — Successful operation
  • '04' — Accepted on OPEN (treated as success)
  • '10' — End of file (only on sequential READ; sets END-OF-FILE = 'Y')
  • Any other value — DISPLAY error message with file name and return code, then PERFORM 9999-ABEND-PROGRAM (CALL CEE3ABD)

Performance and Batch Window Analysis

11.1 Performance Characteristics

The job has two distinct performance phases:

  1. SORT Phase (STEP010): Reads entire TRANSACT VSAM, sorts by card number + tran ID, reformats keys. Performance depends on TRANSACT volume and available sort work space.
  2. Statement Generation (STEP040): All transactions are loaded into a fixed-size in-memory table (WS-TRNX-TABLE: 51 cards × 10 transactions = 510 entries max). For each XREF card: 1 random CUSTFILE read + 1 random ACCTFILE read + in-memory table scan.
Scalability Limitation: The 2D array WS-TRNX-TABLE is hard-coded to 51 card groups with 10 transactions each. If the TRXFL VSAM contains more than 51 distinct cards or more than 10 transactions for any single card, the program will silently overwrite memory (no bounds checking), leading to data corruption or S0C4 abend.
