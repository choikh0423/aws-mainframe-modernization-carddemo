Business Flow Analysis

1.1 Business Context

  • What: Reads a flat file of daily credit-card transactions, validates each against the Card Cross-Reference and Account Master, and posts valid transactions to the Transaction Master VSAM file. Updates account current balances and cycle-level credits/debits. Maintains the Transaction Category Balance file for downstream interest calculation.
  • Who: Downstream consumers include the Monthly Interest Calculation batch (INTCALC/CBACT04C), the Transaction Report job (TRANREPT/CBTRN03C), and the Statement Generation job (CREASTMT/CBSTM03A).
  • When: Runs daily after business-day close, typically following the DAILY-TransactionBackup job stream which backs up the previous day’s transaction VSAM and resets it.
  • Why: Core operational requirement—ensures all authorized card transactions are reflected in account balances, category-level running totals, and the permanent transaction ledger.
  • Outcome: Transaction Master populated with validated transactions; Account Master balances updated; Transaction Category Balance file updated; rejected transactions captured with reason codes for investigation.

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  STEP15 - EXEC PGM=CBTRN02C
    INPUTS:
      - DALYTRAN: AWS.M2.CARDDEMO.DALYTRAN.PS         (sequential read)
      - XREFFILE: AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS  (keyed random read)
      - ACCTFILE: AWS.M2.CARDDEMO.ACCTDATA.VSAM.KSDS  (keyed random I-O)
      - TCATBALF: AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS  (keyed random I-O)
    OUTPUTS:
      - TRANFILE: AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS  (keyed output/write)
      - DALYREJS: AWS.M2.CARDDEMO.DALYREJS(+1)         (sequential output)

    PROCESSING:
      1. Open all 6 files (ABEND if any open fails)
      2. READ DALYTRAN-FILE until EOF
         a. Increment WS-TRANSACTION-COUNT
         b. PERFORM 1500-VALIDATE-TRAN:
            i.  1500-A-LOOKUP-XREF: READ XREFFILE by DALYTRAN-CARD-NUM
                - INVALID KEY → reason 100 → skip to reject
            ii. 1500-B-LOOKUP-ACCT: READ ACCTFILE by XREF-ACCT-ID
                - INVALID KEY → reason 101
                - COMPUTE temp-bal = cyc-credit - cyc-debit + tran-amt
                  If temp-bal > CREDIT-LIMIT → reason 102
                - If ACCT-EXPIRATION-DATE < TRAN-ORIG-TS → reason 103
         c. If validation passed (reason = 0):
            PERFORM 2000-POST-TRANSACTION:
              - Map DALYTRAN fields → TRAN-RECORD
              - Generate DB2-format timestamp for TRAN-PROC-TS
              - 2700-UPDATE-TCATBAL: READ/REWRITE (or CREATE) TCATBAL
              - 2800-UPDATE-ACCOUNT-REC: ADD amount to ACCT-CURR-BAL
                + ACCT-CURR-CYC-CREDIT (if ≥ 0) or CYC-DEBIT (if < 0)
                REWRITE ACCTFILE
              - 2900-WRITE-TRANSACTION-FILE: WRITE to TRANSACT VSAM
         d. If validation failed (reason ≠ 0):
            Increment WS-REJECT-COUNT
            PERFORM 2500-WRITE-REJECT-REC: WRITE to DALYREJS
      3. Close all files
      4. Display counts: TRANSACTIONS PROCESSED / REJECTED
      5. If WS-REJECT-COUNT > 0: set RETURN-CODE = 4
         Else: RETURN-CODE = 0
    RC: 0=All valid, 4=Some rejects, 999=ABEND (file I/O error)

3.4 Scheduler Dependencies

Note: POSTTRAN is not directly in the Control-M schedule but is logically positioned between the DAILY-TransactionBackup stream (which empties the TRANSACT VSAM) and the next day’s CICS open. It must run after TRANBKP backs up and resets the VSAM and before OPENFIL reopens CICS files.

Performance and Batch Window Analysis

11.1 Performance Characteristics

CBTRN02C processes each input record with up to 5 VSAM I/O operations per record:

  1. READ DALYTRAN (sequential)
  2. READ XREFFILE (random, by card number)
  3. READ ACCTFILE (random, by account ID)
  4. READ + REWRITE (or WRITE) TCATBALF (random, by composite key)
  5. REWRITE ACCTFILE (random)
  6. WRITE TRANSACT (random)
Performance note: The random VSAM access pattern (one READ per record across 3 different KSDS files) means elapsed time scales linearly with input volume. For large volumes, consider pre-sorting DALYTRAN by card number to improve VSAM buffering locality on the XREFFILE reads.
