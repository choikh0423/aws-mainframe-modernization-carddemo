Business Flow Analysis

1.1 Business Context

  • What: A multi-step job that (1) unloads the TRANSACT VSAM to a sequential backup, (2) filters the backup by a configurable date range and sorts by card number, then (3) produces a formatted, paginated transaction detail report enriched with transaction type descriptions, category descriptions, and account IDs from cross-reference lookups.
  • Who: Consumed by operations, finance, and audit teams. Downstream of the Daily Transaction Posting job (POSTTRAN/CBTRN02C) which populates the TRANSACT VSAM.
  • When: Triggered on demand when business users require a transaction listing for a specific date range. Typically run after POSTTRAN has completed for the reporting period.
  • Why: Provides a human-readable, print-ready report of card transactions grouped by card number with running totals at page, account, and grand levels for reconciliation and audit purposes.
  • Outcome: A GDG-versioned report file (TRANREPT(+1)) containing a formatted 133-byte print report with headers, detail lines, and three levels of totals (page, account, grand).

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  STEP05R (REPROC) — EXEC PROC=REPROC, CNTLLIB=AWS.M2.CARDDEMO.CNTL
    PRC001: EXEC PGM=IDCAMS
    INPUTS:
      - FILEIN:  AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS  (VSAM KSDS input)
    OUTPUTS:
      - FILEOUT: AWS.M2.CARDDEMO.TRANSACT.BKUP(+1)   (sequential, FB/350)
    PROCESSING:
      REPRO INFILE(FILEIN) OUTFILE(FILEOUT)
      (Full unload of TRANSACT VSAM to sequential backup)
    RC: 0=Success, 4=Empty input, 12+=Fatal error

  STEP05R (SORT) — EXEC PGM=SORT
    INPUTS:
      - SORTIN: AWS.M2.CARDDEMO.TRANSACT.BKUP(+1)    (sequential, FB/350)
    OUTPUTS:
      - SORTOUT: AWS.M2.CARDDEMO.TRANSACT.DALY(+1)    (sequential, FB/350)
    SYMNAMES:
      TRAN-CARD-NUM: offset 263, length 16, ZD
      TRAN-PROC-DT:  offset 305, length 10, CH
      PARM-START-DATE: C'2022-01-01'
      PARM-END-DATE:   C'2022-07-06'
    PROCESSING:
      SORT FIELDS=(TRAN-CARD-NUM,A)
      INCLUDE COND=(TRAN-PROC-DT,GE,PARM-START-DATE,AND,
                    TRAN-PROC-DT,LE,PARM-END-DATE)
    RC: 0=Success, 16=Fatal

  STEP10R — EXEC PGM=CBTRN03C
    INPUTS:
      - TRANFILE: AWS.M2.CARDDEMO.TRANSACT.DALY(+1)         (sequential)
      - CARDXREF: AWS.M2.CARDDEMO.CARDXREF.VSAM.KSDS        (keyed random)
      - TRANTYPE: AWS.M2.CARDDEMO.TRANTYPE.VSAM.KSDS        (keyed random)
      - TRANCATG: AWS.M2.CARDDEMO.TRANCATG.VSAM.KSDS        (keyed random)
      - DATEPARM: AWS.M2.CARDDEMO.DATEPARM                    (sequential)
    OUTPUTS:
      - TRANREPT: AWS.M2.CARDDEMO.TRANREPT(+1)               (sequential)
    PROCESSING:
      1. Open all 6 files (ABEND if any open fails)
      2. Read DATEPARM → WS-START-DATE, WS-END-DATE
      3. Loop: READ TRANFILE until EOF
         a. Secondary date filter: TRAN-PROC-TS(1:10) in range
         b. Control break on TRAN-CARD-NUM change:
            - Write account totals for previous card
            - Lookup CARDXREF by new card number → XREF-ACCT-ID
         c. Lookup TRANTYPE by TRAN-TYPE-CD → TRAN-TYPE-DESC
         d. Lookup TRANCATG by TRAN-TYPE-CD + TRAN-CAT-CD → TRAN-CAT-TYPE-DESC
         e. Write detail line (1120-WRITE-DETAIL)
         f. Every 20 lines: write page totals, new headers
      4. At EOF: write final page totals and grand totals
      5. Close all files
    RC: 0=Normal completion, 999=ABEND (file I/O or lookup error)

2.3 Step Dependency and Condition Code Logic

StepProgramExecutes IfCondition Code Meaning
STEP05R (REPROC)IDCAMSAlways (first step)0 = VSAM unloaded successfully
4 = Empty input VSAM (no records to copy)
12+ = Fatal IDCAMS error
STEP05R (SORT)SORTAlways (no COND= coded)0 = Sort and filter completed successfully
16 = Fatal sort error
STEP10RCBTRN03CAlways (no COND= coded)0 = Report generated (no explicit RETURN-CODE set)
999 = ABEND via CEE3ABD (file I/O or reference lookup failure)
Design gap: No COND= parameters exist on any step. If STEP05R (REPROC) fails with RC=12, the SORT and CBTRN03C steps will still execute against missing or empty input, likely causing cascading failures.

3.4 Scheduler Dependencies

Note: TRANREPT is not in the Control-M schedule (CardDemo.controlm). It is an on-demand job that can be submitted whenever a transaction report is required. It must run after POSTTRAN has populated the TRANSACT VSAM for the desired reporting period. Since all VSAM files are opened with DISP=SHR, this job can run concurrently with CICS online processing. 
  POSTTRAN (populates TRANSACT VSAM)
       │
       │  (TRANSACT VSAM must contain data for report period)
       ▼
  TRANREPT (on-demand)
  ├── STEP05R (REPROC): Unload VSAM → TRANSACT.BKUP(+1)
  ├── STEP05R (SORT):   Filter + Sort → TRANSACT.DALY(+1)
  └── STEP10R (CBTRN03C): Generate report → TRANREPT(+1)
       │
       ▼
  Report available for viewing / printing

Performance and Batch Window Analysis

11.1 Performance Characteristics

The job has three distinct I/O phases:

  1. STEP05R (REPROC): Sequential REPRO of TRANSACT VSAM — I/O bound, typically fast for moderate volumes
  2. STEP05R (SORT): DFSORT with INCLUDE filtering and ascending sort by card number — efficient for volumes typical of daily transactions
  3. STEP10R (CBTRN03C): For each input record, up to 3 random VSAM READ operations (CARDXREF, TRANTYPE, TRANCATG) plus one sequential WRITE to the report file. The XREF lookup is optimized by control break — only performed when the card number changes.
Performance note: Since input is pre-sorted by card number (from the SORT step), CARDXREF lookups are minimized to one per unique card. TRANTYPE and TRANCATG lookups occur for every record but these are small VSAM files with fast random access. The report WRITE is sequential and inherently fast.
