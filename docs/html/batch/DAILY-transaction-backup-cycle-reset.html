Business Flow Analysis

1.1 Business Context

  • What: A four-job stream that performs the daily transaction VSAM cycle reset. It closes CICS-managed VSAM files, backs up the Transaction Master to a GDG generation, deletes and redefines the empty VSAM cluster (resetting it for the next day’s transactions), pauses briefly for I/O stabilization, and finally reopens all files in CICS.
  • Who: Downstream consumers include the POSTTRAN batch job (which writes new transactions into the freshly emptied VSAM), and CICS online transaction processing (which requires files to be reopened before users can enter transactions).
  • When: Runs daily, triggered by Control-M scheduler. Executes every day of the year (DAYS=ALL). Must complete before 23:00.
  • Why: The Transaction Master VSAM accumulates all posted transactions during the day. Before the next posting cycle, the previous day’s data must be preserved (backup to GDG) and the file must be emptied to receive new postings. CICS files must be closed during this process to prevent online access conflicts with batch utilities.
  • Outcome: Transaction VSAM backed up to GDG generation (+1); VSAM cluster deleted and redefined (empty); CICS files reopened for online processing; system ready for next day’s POSTTRAN batch cycle.

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  ═══════════════════════════════════════════════════════════════
  JOB 1: CLOSEFIL — Close VSAM files in CICS
  ═══════════════════════════════════════════════════════════════
  STEP: CLCIFIL  EXEC PGM=SDSF
    DD:
      ISFOUT  → SYSOUT=*  (SDSF output)
      CMDOUT  → SYSOUT=*  (Command output)
      ISFIN   ← Inline commands (5 CEMT SET FIL CLO commands)
    PROCESSING:
      1. Issue: /F CICSAWSA,'CEMT SET FIL(TRANSACT) CLO'
      2. Issue: /F CICSAWSA,'CEMT SET FIL(CCXREF  ) CLO'
      3. Issue: /F CICSAWSA,'CEMT SET FIL(ACCTDAT ) CLO'
      4. Issue: /F CICSAWSA,'CEMT SET FIL(CXACAIX ) CLO'
      5. Issue: /F CICSAWSA,'CEMT SET FIL(USRSEC  ) CLO'
    RC: 0=Success

  ═══════════════════════════════════════════════════════════════
  JOB 2: TRANBKP — Backup and Reset Transaction VSAM
  ═══════════════════════════════════════════════════════════════
  STEP: STEP05R  EXEC PROC=REPROC, CNTLLIB=AWS.M2.CARDDEMO.CNTL
    Proc REPROC invokes PGM=IDCAMS with REPROCT control card:
      REPRO INFILE(FILEIN) OUTFILE(FILEOUT)
    DD overrides:
      PRC001.FILEIN  → AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS (SHR)
      PRC001.FILEOUT → AWS.M2.CARDDEMO.TRANSACT.BKUP(+1)
                       (NEW,CATLG,DELETE) LRECL=350 RECFM=FB
    PROCESSING:
      1. REPRO all records from VSAM KSDS to sequential GDG(+1)
    RC: 0=Success, 4=Warning (empty input), 12+=Error

  STEP: STEP05  EXEC PGM=IDCAMS
    DD:
      SYSPRINT → SYSOUT=*
      SYSIN    ← Inline IDCAMS commands
    PROCESSING:
      1. DELETE AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS CLUSTER
         IF MAXCC LE 08 THEN SET MAXCC = 0
      2. DELETE AWS.M2.CARDDEMO.TRANSACT.VSAM.AIX ALTERNATEINDEX
         IF MAXCC LE 08 THEN SET MAXCC = 0
    RC: 0=Success (RC≤8 forced to 0)

  STEP: STEP10  EXEC PGM=IDCAMS, COND=(4,LT)
    Executes only if prior STEP05 RC ≤ 4
    DD:
      SYSPRINT → SYSOUT=*
      SYSIN    ← Inline IDCAMS commands
    PROCESSING:
      1. DEFINE CLUSTER:
         NAME(AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS)
         CYLINDERS(1 5), VOLUMES(AWSHJ1)
         KEYS(16 0), RECORDSIZE(350 350)
         SHAREOPTIONS(2 3), ERASE, INDEXED
         DATA(AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS.DATA)
         INDEX(AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS.INDEX)
    RC: 0=Success, 12+=Error

  ═══════════════════════════════════════════════════════════════
  JOB 3: WAITSTEP — Stabilization Pause
  ═══════════════════════════════════════════════════════════════
  STEP: WAIT  EXEC PGM=COBSWAIT
    DD:
      STEPLIB  → AWS.M2.CARDDEMO.LOADLIB (SHR)
      SYSOUT   → SYSOUT=*
      SYSIN    ← 00003600 (36 seconds in centiseconds)
    PROCESSING:
      1. ACCEPT PARM-VALUE FROM SYSIN   → "00003600"
      2. MOVE PARM-VALUE TO MVSWAIT-TIME (PIC 9(8) COMP)
      3. CALL 'MVSWAIT' USING MVSWAIT-TIME
      4. STOP RUN
    RC: 0=Success

  ═══════════════════════════════════════════════════════════════
  JOB 4: OPENFIL — Reopen VSAM files in CICS
  ═══════════════════════════════════════════════════════════════
  STEP: OPCIFIL  EXEC PGM=SDSF
    DD:
      ISFOUT  → SYSOUT=*  (SDSF output)
      CMDOUT  → SYSOUT=*  (Command output)
      ISFIN   ← Inline commands (5 CEMT SET FIL OPE commands)
    PROCESSING:
      1. Issue: /F CICSAWSA,'CEMT SET FIL(TRANSACT) OPE'
      2. Issue: /F CICSAWSA,'CEMT SET FIL(CCXREF  ) OPE'
      3. Issue: /F CICSAWSA,'CEMT SET FIL(ACCTDAT ) OPE'
      4. Issue: /F CICSAWSA,'CEMT SET FIL(CXACAIX ) OPE'
      5. Issue: /F CICSAWSA,'CEMT SET FIL(USRSEC  ) OPE'
    RC: 0=Success

3.4 Scheduler Dependencies

Control-M Configuration: The DAILY-TransactionBackup smart folder defines a strict linear dependency chain using INCOND/OUTCOND pairs. Each job signals completion via a positive OUTCOND which is consumed as a prerequisite INCOND by the next job. All jobs run under application CARD-DEMO, sub-application CTRLM, scheduled for ALL days with MAXRERUN=5.

Note: The primary data record for this job stream is the Transaction VSAM record (350 bytes, key 16 bytes at offset 0). The full record layout is defined in copybook CVTRA05Y (used by POSTTRAN/CBTRN02C). This job stream does not parse individual fields — it operates at the dataset level (REPRO, DELETE, DEFINE).

Checkpoint, Restart, and Recovery

8.1 Checkpoint Strategy

No Checkpoint/Restart: This job stream implements no checkpoint logic. Each job is either fully successful or must be re-run from the beginning. The Control-M MAXRERUN=5 setting allows automatic retry of failed jobs.

8.2 Restart Procedures

Error Handling and Abend Resolution

9.1 Error Handling Flow

  ┌─────────────────────────────────────────────────────────────┐
  │                    ERROR HANDLING SUMMARY                    │
  └─────────────────────────────────────────────────────────────┘

  CLOSEFIL / OPENFIL:
    SDSF command failure → Job RC ≠ 0 → Control-M MAXRERUN=5

  TRANBKP STEP05R (REPRO):
    VSAM I/O error → IDCAMS RC=12+ → Job fails
    Empty VSAM → IDCAMS RC=4 (warning, acceptable)

  TRANBKP STEP05 (DELETE):
    Cluster not found → RC=8 → Forced to 0 by IF MAXCC LE 08
    Catalog error → RC=12+ → Job fails (STEP10 skipped via COND)

  TRANBKP STEP10 (DEFINE):
    Only executes if STEP05 RC ≤ 4 (COND=(4,LT))
    Duplicate cluster → RC=12 → Job fails

  WAITSTEP (COBSWAIT):
    MVSWAIT system service failure → Unlikely; STOP RUN returns RC=0
    Invalid PARM-VALUE → Undefined behavior (no input validation)

13.1 Known Issues

Issue IDDescriptionImpactSuggested Fix
KI-001Typo in TRANBKP JCL comment: “TRANSACATION” (should be “TRANSACTION”) appears twice (STEP05 and STEP10 comments)Low — cosmetic, no processing impactCorrect spelling in JCL comments
KI-002No record count reconciliation: REPRO does not verify or report the number of records backed up vs. the number in the source VSAMMedium — silent data loss could go undetected if REPRO is partialAdd IDCAMS LISTCAT to capture record count before REPRO; compare with REPRO output count
KI-003COBSWAIT has no input validation: if SYSIN contains non-numeric data or is missing, the MOVE to PIC 9(8) COMP will produce undefined behavior (likely S0C7)Low — static inline JCL data; but fragile if ever parameterizedAdd NUMERIC test on PARM-VALUE before MOVE; set default or ABEND gracefully
KI-004No conditional dependency between STEP05R and STEP05 in TRANBKP: if REPRO fails (RC=12), STEP05 still executes and deletes the VSAM cluster, losing the only copy of the dataHigh — potential data loss if REPRO fails silently and no other backup existsAdd COND=(4,LT) to STEP05 to skip DELETE if REPRO failed; or restructure as separate jobs with Control-M conditions
KI-005VSAM AIX is deleted but never redefined: STEP05 deletes TRANSACT.VSAM.AIX but STEP10 only defines the base cluster. If any program expects the AIX to exist, it will fail.Medium — depends on whether downstream programs use the AIXAdd DEFINE ALTERNATEINDEX and DEFINE PATH after DEFINE CLUSTER in STEP10, or confirm AIX is not required
KI-006Fixed 36-second wait is arbitrary: the WAITSTEP duration is hardcoded and not derived from any system metric. On fast systems it wastes time; on slow systems it may be insufficient.Low — minor operational inefficiencyReplace with a polling mechanism that verifies catalog propagation, or parameterize via symbolic

KI-008No NOTIFY or email on job stream completion/failure: operations team has no proactive alerting for this critical daily processMedium — failures may go unnoticed until POSTTRAN or CICS users report issuesAdd Control-M SHOUT or DO MAIL action on completion/failure
