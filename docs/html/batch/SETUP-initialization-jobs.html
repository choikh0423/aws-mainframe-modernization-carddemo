Business Flow Analysis

1.1 Business Context

  • What: Provisions the complete data infrastructure for the CardDemo application — defines all VSAM clusters (KSDS, ESDS, RRDS), GDG base entries, alternate indexes, CICS CSD resource definitions, and DB2 database objects required before any online or batch processing can occur.
  • Who: Platform operations team, system programmers, and DBAs execute these jobs during initial environment setup, migration to a new LPAR, or disaster recovery rebuild.
  • When: One-time during environment provisioning. Re-run as needed for data refresh, environment clone, or after catastrophic failure.
  • Why: All CardDemo online transactions (CICS) and batch jobs depend on these VSAM files, GDG structures, CICS resource definitions, and DB2 tables existing and being properly initialized with seed data.
  • Outcome: A fully provisioned CardDemo environment with all 9 VSAM KSDS clusters defined and loaded, 10 GDG bases established, user security data seeded, CICS CSD group installed, and DB2 transaction tables created and populated.

2.2 Detailed Step-by-Step

D1 — VSAM File Definition Jobs (Common Pattern)

Each D1 job follows a consistent 3-step pattern (some with additional AIX steps):

StepProgramActionNotes
CLCIFILSDSFClose CICS filesOnly in CARDFILE, CUSTFILE, TRANFILE (files open in CICS)
STEP05IDCAMSDELETE existing cluster (+ AIX if applicable)IF MAXCC LE 08 / SET MAXCC=0 for idempotency
STEP10IDCAMSDEFINE CLUSTER (KSDS)Specifies KEYS, RECORDSIZE, SHAREOPTIONS, VOLUMES
STEP15IDCAMSREPRO from PS flat file to VSAMLoads seed data
STEP20/40IDCAMSDEFINE ALTERNATEINDEXCARDFILE, TRANFILE, XREFFILE only
STEP25/50IDCAMSDEFINE PATHAssociates AIX with base cluster
STEP30/60IDCAMSBLDINDEXBuilds AIX from base cluster data
OPCIFILSDSFOpen CICS filesOnly in CARDFILE, CUSTFILE, TRANFILE

D2 — GDG Definition Jobs

JobStepsAction
DEFGDGBSTEP05 (IDCAMS)DEFINE 6 GDG bases: TRANSACT.BKUP, TRANSACT.DALY, TRANREPT, TCATBALF.BKUP, SYSTRAN, TRANSACT.COMBINED (all LIMIT(5) SCRATCH)
DEFGDGDSTEP10-60 (IDCAMS + IEBGENER)DEFINE 3 GDG bases (TRANTYPE.BKUP, TRANCATG.PS.BKUP, DISCGRP.BKUP) and load first generation of each using IEBGENER from PS source
DALYREJSSTEP05 (IDCAMS)DEFINE GDG base: DALYREJS (LIMIT(5) SCRATCH)
REPTFILESTEP05 (IDCAMS)DEFINE GDG base: TRANREPT (LIMIT(10)) — higher limit for report retention

D3 — Other Setup Jobs

JobStepsAction
DUSRSECJPREDEL, STEP01, STEP02, STEP03Delete old PS → IEBGENER inline data to PS → IDCAMS DEFINE KSDS → REPRO PS to VSAM. Creates user security file with 10 users (5 admin + 5 regular).
ESDSRRDSPREDEL, STEP01-05Same inline data → PS, then DEFINE ESDS cluster + REPRO, then DEFINE RRDS cluster + REPRO. Creates alternative VSAM access methods for security data.
TRANIDXSTEP20, STEP25, STEP30DEFINE AIX on TRANSACT.VSAM.KSDS (KEYS 26,304 = processed timestamp), DEFINE PATH, BLDINDEX. Standalone AIX job for transaction file.
CBADMCDJSTEP1 (DFHCSDUP)Define CICS CSD resources: LIBRARY, 17 MAPSETs, 14 PROGRAMs, 5 TRANSACTIONs in GROUP(CARDDEMO)
CREADB21FREEPLN, CRCRDDB, LDTTYPE, RUNTEP2, LDTCCATFree existing DB2 plans → create database/tables via DSNTIAD → load TRANTYPE data → load TRANCATG data via DSNTEP4

2.3 Condition Code Logic

JobCondition Code HandlingPurpose
D1 Jobs (ACCTFILE, XREFFILE, etc.)IF MAXCC LE 08 THEN SET MAXCC = 0Allows DELETE to fail (RC=8) when cluster does not exist, enabling re-run
TCATBALF, TRANCATG, TRANTYPE, DISCGRPSET MAXCC = 0Unconditionally resets after DELETE — always continues

DEFGDGD (STEP20, 40, 60)COND=(0,NE) on IEBGENEROnly load first generation if prior DEFINE succeeded (CC=0)

3.4 Scheduler Dependencies

Note: These setup jobs are not defined in the Control-M scheduler (app/scheduler/CardDemo.controlm). They are run manually by operations staff during environment provisioning. The dependency order is enforced procedurally by the operations runbook.

Required execution order:

  1. D1 jobs first — VSAM clusters must exist before GDG jobs reference them (DEFGDGD loads from PS files that correspond to VSAM datasets)
  2. D2 jobs second — GDG bases must exist before daily batch cycle can produce generation datasets
  3. D3 jobs last — TRANIDX requires TRANSACT VSAM to exist (from TRANFILE); CBADMCDJ defines CICS resources pointing to VSAM files; CREADB21 is independent but logically last

Data Flow Analysis

6.1 Transformation Map

The setup jobs perform no data transformation. All operations are either:

  • Structure definition — DEFINE CLUSTER/GDG/AIX/PATH creates empty containers
  • Byte-for-byte copy — REPRO and IEBGENER copy records without modification from flat files into VSAM clusters or from inline data into PS files
  • Index construction — BLDINDEX reads base cluster records and builds AIX entries based on key position/length

6.3 Control Totals

No control total logic exists in these setup jobs. IDCAMS REPRO reports record counts in SYSPRINT output but there is no programmatic validation of expected vs. actual counts. The DUSRSECJ job has exactly 10 inline records (5 ADMIN + 5 USER) which can be verified manually.

Checkpoint, Restart, and Recovery

8.1 Checkpointing Strategy

None. No checkpoint/restart logic is implemented in any of the 18 setup jobs. This is acceptable because:

  • Each job is idempotent — DELETE-then-DEFINE pattern allows complete re-execution
  • Data volumes are small (seed data for a demo application)
  • Jobs complete in seconds, making checkpoint overhead unnecessary

8.2 Restart Procedures

  • Any D1 job fails: Simply re-submit the job. The DELETE step handles pre-existing clusters.
  • Any D2 job fails: Re-submit. IF LASTCC=12 THEN SET MAXCC=0 handles pre-existing GDG bases.
  • DUSRSECJ/ESDSRRDS fails: Re-submit. PREDEL step with IEFBR14 and DELETE handle cleanup.
  • CBADMCDJ fails: Uncomment DELETE GROUP(CARDDEMO) in SYSIN and re-submit.
  • CREADB21 fails: Enable FREEPLN step (remove TYPRUN=SCAN), fix issue, re-submit. DDL is CREATE-or-fail so may need manual DROP first.
