Business Flow Analysis

1.1 Business Context

  • What: Produces a formatted flat-file report showing running transaction category balances per account, sorted by Account ID, Transaction Type Code, and Category Code. Each line shows the balance formatted with two decimal places.
  • Who: Consumed by Finance/Operations staff for balance reconciliation, audit reviews, and as input to downstream interest calculation verification.
  • When: Triggered on-demand whenever operations or audit requires a current snapshot of transaction category balances. Typically run after POSTTRAN has updated the TCATBALF VSAM.
  • Why: Provides human-readable visibility into the running category-level balances that drive interest calculations (INTCALC/CBACT04C). Used for reconciliation and exception investigation.
  • Outcome: A fixed-format sequential report file (TCATBALF.REPT) with one line per category balance record, sorted and formatted for readability.

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  STEP 1: DELDEF - EXEC PGM=IEFBR14
    PURPOSE: Delete the previous report file to ensure a clean run
    DD THEFILE:
      - DSN=AWS.M2.CARDDEMO.TCATBALF.REPT
      - DISP=(MOD,DELETE)
      - UNIT=SYSDA, SPACE=(TRK,(1,1),RLSE)
    RESULT: Previous TCATBALF.REPT is deleted (or no-op if absent)

  STEP 2: STEP05R - EXEC PROC=REPROC
    PURPOSE: Unload TCATBALF VSAM KSDS to sequential backup
    CNTLLIB: AWS.M2.CARDDEMO.CNTL
    DD PRC001.FILEIN:
      - DSN=AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS (DISP=SHR)
      - VSAM KSDS (LRECL=50)
    DD PRC001.FILEOUT:
      - DSN=AWS.M2.CARDDEMO.TCATBALF.BKUP(+1)
      - DISP=(NEW,CATLG,DELETE)
      - DCB=(LRECL=50,RECFM=FB,BLKSIZE=0)
      - SPACE=(CYL,(1,1),RLSE)
    RESULT: Full sequential copy of VSAM in GDG generation +1

  STEP 3: STEP10R - EXEC PGM=SORT
    PURPOSE: Sort records and format report output
    DD SORTIN:
      - DSN=AWS.M2.CARDDEMO.TCATBALF.BKUP(+1) (DISP=SHR)
    DD SYMNAMES (instream):
      - TRANCAT-ACCT-ID,1,11,ZD
      - TRANCAT-TYPE-CD,12,2,CH
      - TRANCAT-CD,14,4,ZD
      - TRAN-CAT-BAL,18,11,ZD
    DD SYSIN (instream):
      - SORT FIELDS=(TRANCAT-ACCT-ID,A,TRANCAT-TYPE-CD,A,TRANCAT-CD,A)
      - OUTREC FIELDS=(TRANCAT-ACCT-ID,X,
            TRANCAT-TYPE-CD,X,
            TRANCAT-CD,X,
            TRAN-CAT-BAL,EDIT=(TTTTTTTTT.TT),9X)
    DD SORTOUT:
      - DSN=AWS.M2.CARDDEMO.TCATBALF.REPT
      - DISP=(NEW,CATLG,DELETE)
      - DCB=(LRECL=40,RECFM=FB,BLKSIZE=0)
      - SPACE=(CYL,(1,1),RLSE)
    DD SYSOUT: SYSOUT=*
    RESULT: Sorted, formatted report written to TCATBALF.REPT

3.4 Scheduler Dependencies

Note: PRTCATBL is not in the Control-M schedule. It is an on-demand reporting job that can run at any time because it only reads the TCATBALF VSAM (via REPROC with DISP=SHR). It does not require CICS file closure. However, for meaningful results it should be run after POSTTRAN has posted the day’s transactions to TCATBALF. 
  Logical Dependency (not enforced by scheduler):

  POSTTRAN                    PRTCATBL
  ────────                    ────────
  Posts transactions    ──▶   Reads TCATBALF VSAM (SHR)
  to TCATBALF VSAM            Produces balance report

  No hard prerequisite; PRTCATBL can run anytime,
  but results reflect the VSAM state at execution time.

7.3 OUTREC EDIT Mask Analysis

The EDIT=(TTTTTTTTT.TT) mask formats the 11-byte zoned decimal TRAN-CAT-BAL field:

  • T = source digit placeholder (suppresses leading zeros with spaces)
  • . = literal decimal point inserted in output
  • Input: S9(09)V99 (9 integer digits + 2 implied decimal digits = 11 bytes)
  • Output: TTTTTTTTT.TT = 9 integer positions + decimal point + 2 decimal positions = 12 characters
  • Example: Input 00000050025 → Output 500.25
Limitation: The EDIT mask uses T (suppress leading zeros) which replaces leading zeros with spaces. This means negative balances (from the S in S9(09)V99) lose their sign in the formatted output. The sign nibble in the zoned decimal low-order byte is not rendered by the EDIT mask.

Checkpoint, Restart, and Recovery

8.1 Checkpoint Strategy

Not applicable. PRTCATBL is a read-only reporting job. It does not modify the source VSAM file. No checkpoint/restart logic is needed because:
  • The VSAM is accessed DISP=SHR (read-only)
  • Output files (BKUP, REPT) can simply be re-created on rerun
  • No data inconsistency can result from a mid-job failure

8.2 Restart Procedures

Failure ScenarioRestart StepPrerequisitesData Reset Required
STEP05R fails (VSAM unload error)Resubmit entire jobVerify TCATBALF VSAM is accessibleDelete partial TCATBALF.BKUP(+1) if cataloged
STEP10R fails (SORT error)Resubmit from STEP10R (if BKUP exists) or entire jobVerify TCATBALF.BKUP(+1) exists and is completeDelete partial TCATBALF.REPT
JCL error (before execution)Fix JCL and resubmitNoneNone

8.3 Recovery Diagram

  Normal: DELDEF → STEP05R (unload) → STEP10R (sort/format) → Done

  Failure at STEP05R:
    1. VSAM unload failed (file not found, VSAM error)
    2. BKUP(+1) may be partially written
    3. Recovery: Delete BKUP(+1), fix VSAM issue, resubmit job

  Failure at STEP10R:
    1. SORT failed (control card error, space issue)
    2. BKUP(+1) is intact (already written)
    3. Recovery: Fix SORT issue, resubmit from STEP10R
       (or resubmit entire job — DELDEF and STEP05R are idempotent)

Error Handling and Abend Resolution

9.1 Error Flow Diagram

  DELDEF (IEFBR14)
    │
    ├── File not found → RC=0 (normal for first run)
    └── Permanent I/O error → S001 ABEND (unlikely)

    │
    ├── VSAM not found → ABEND (dataset not cataloged)
    ├── VSAM is empty → RC=0 (empty output)

    ├── SORTIN empty → RC=0 (empty SORTOUT)
    ├── SORTIN not found → RC=16 (SORT failure)

    ├── SORTOUT space exhaustion → S*37 ABEND
