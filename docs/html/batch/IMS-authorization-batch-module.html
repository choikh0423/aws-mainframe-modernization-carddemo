Business Flow Analysis

1.1 Business Context

  • What: A five-job IMS batch module that maintains the Payment Authorization Database (PAUTHDB). The cycle purges expired authorization records, unloads the database to flat files, performs HD reorganization via the IMS utility DFSURGU0, reloads the database from flat files, and provides an alternative GSAM-based unload path for downstream consumption.
  • Who: Consumed by IMS DBA operations, authorization processing online transactions (CICS/IMS), and downstream analytics or migration pipelines that need flat-file extracts of authorization data.
  • When: Run periodically (weekly or monthly) during an IMS offline maintenance window, or on-demand when the authorization database requires reorganization due to space reclamation or performance degradation.
  • Why: IMS HIDAM databases accumulate delete-flagged segments and free-space fragmentation over time. Periodic purge-and-reorganize cycles are essential to maintain query performance, reclaim DASD space, and ensure data integrity of the authorization subsystem.
  • Outcome: Expired authorization detail and summary segments are purged; the HIDAM database is reorganized with optimal pointer chains; flat-file backups of root and child segments are available for disaster recovery; GSAM exports are available for non-IMS consumers.

2.2 Technical Flow Diagram – Detailed (Step-by-Step)

  ═══════════════════════════════════════════════════════════════════
  C1: CBPAUP0J — Purge Expired Authorizations (IMS BMP)
  ═══════════════════════════════════════════════════════════════════
  STEP01 - EXEC PGM=DFSRRC00, PARM='BMP,CBPAUP0C,PSBPAUTB'
    PSB: PSBPAUTB (PROCOPT=AP, DB PCB for DBPAUTP0)
    PROCESSING:
      1. 1000-INITIALIZE: Accept DATE/DAY, read SYSIN parms
         - Parse expiry-days (default 5), chkp-freq (default 5),
           chkp-dis-freq (default 10), debug flag
      2. Loop: 2000-FIND-NEXT-AUTH-SUMMARY (EXEC DLI GN PAUTSUM0)
         Until END-OF-AUTHDB (DIBSTAT='GB')
         a. For each root segment found:
            - 3000-FIND-NEXT-AUTH-DTL (EXEC DLI GNP PAUTDTL1)
              Until NO-MORE-AUTHS (DIBSTAT='GE' or 'GB')
            - 4000-CHECK-IF-EXPIRED:
              COMPUTE WS-AUTH-DATE = 99999 - PA-AUTH-DATE-9C
              COMPUTE WS-DAY-DIFF = CURRENT-YYDDD - WS-AUTH-DATE
              IF WS-DAY-DIFF ≥ WS-EXPIRY-DAYS → QUALIFIED-FOR-DELETE
                 Adjust approved/declined counters & amounts
            - 5000-DELETE-AUTH-DTL (EXEC DLI DLET PAUTDTL1) if qualified
         b. If PA-APPROVED-AUTH-CNT ≤ 0 AND PA-DECLINED-AUTH-CNT ≤ 0:
            6000-DELETE-AUTH-SUMMARY (EXEC DLI DLET PAUTSUM0)
         c. Every P-CHKP-FREQ summaries:
            9000-TAKE-CHECKPOINT (EXEC DLI CHKP)
      3. Final checkpoint, display counts, GOBACK
    RC: 0=Success, 16=ABEND (IMS call failure)

  ═══════════════════════════════════════════════════════════════════
  C2: DBPAUTP0 — HD Reorganization Unload (DFSURGU0)
  ═══════════════════════════════════════════════════════════════════
  STEPDEL - EXEC PGM=IEFBR14
    - Delete prior output: AWS.M2.CARDDEMO.IMSDATA.DBPAUTP0
      DISP=(MOD,DELETE)
  UNLOAD - EXEC PGM=DFSRRC00, PARM=(ULU,DFSURGU0,DBPAUTP0)
    INPUTS:
      - DDPAUTP0: OEM.IMS.IMSP.PAUTHDB (primary DB dataset)
      - DDPAUTX0: OEM.IMS.IMSP.PAUTHDBX (index dataset)
      - RECON1/2/3: DBRC RECON datasets
      - DFSVSAMP: IMS buffer pool parameters
    OUTPUT:
      - DFSURGU1: AWS.M2.CARDDEMO.IMSDATA.DBPAUTP0
        VB, LRECL=27990, BLKSIZE=0, SPACE=(32274,(600,100))
    PROCESSING:
      IMS HD Reorganization Unload utility — reads HIDAM database
      sequentially and writes all segments to a single flat file
      suitable for HD Reorganization Reload
    RC: 0=Success, 4=Warning, 8+=Failure

  ═══════════════════════════════════════════════════════════════════
  C3: UNLDPADB — DLI-mode Unload to Root + Child Flat Files
  ═══════════════════════════════════════════════════════════════════
  STEP0 - EXEC PGM=IEFBR14
    - Delete prior output files:
      AWS.M2.CARDDEMO.PAUTDB.ROOT.FILEO  DISP=(OLD,DELETE,DELETE)
      AWS.M2.CARDDEMO.PAUTDB.CHILD.FILEO DISP=(OLD,DELETE,DELETE)
  STEP01 - EXEC PGM=DFSRRC00, PARM='DLI,PAUDBUNL,PAUTBUNL'
    PSB: PAUTBUNL (PROCOPT=GOTP for DBPAUTP0)
    INPUTS:
      - DDPAUTP0: OEM.IMS.IMSP.PAUTHDB
      - DDPAUTX0: OEM.IMS.IMSP.PAUTHDBX
    OUTPUTS:
      - OUTFIL1: root segments (FB LRECL=100)
      - OUTFIL2: child segments with root key (FB LRECL=206)
    PROCESSING:
      1. 1000-INITIALIZE: Open OPFILE1 & OPFILE2
      2. Loop: 2000-FIND-NEXT-AUTH-SUMMARY
         CALL 'CBLTDLI' GN PAUTSUM0
         - Write root segment to OPFILE1
         - Store PA-ACCT-ID as ROOT-SEG-KEY
         - 3000-FIND-NEXT-AUTH-DTL (CALL 'CBLTDLI' GNP PAUTDTL1)
           Write child segments to OPFILE2
         Until WS-END-OF-ROOT-SEG = 'Y'
      3. 4000-FILE-CLOSE: Close both output files
    RC: 0=Success, 16=ABEND (IMS or file I/O failure)

  ═══════════════════════════════════════════════════════════════════
  C4: LOADPADB — Reload PAUTHDB from Root + Child Flat Files
  ═══════════════════════════════════════════════════════════════════
  STEP01 - EXEC PGM=DFSRRC00, PARM='BMP,PAUDBLOD,PSBPAUTB'
    PSB: PSBPAUTB (PROCOPT=AP for DBPAUTP0)
    INPUTS:
      - INFILE1: root segments (AWS.M2.CARDDEMO.PAUTDB.ROOT.FILEO)
      - INFILE2: child segments (AWS.M2.CARDDEMO.PAUTDB.CHILD.FILEO)
    PROCESSING:
      1. 1000-INITIALIZE: Open INFILE1 & INFILE2
      2. Loop: 2000-READ-ROOT-SEG-FILE → READ INFILE1
         - 2100-INSERT-ROOT-SEG: CALL 'CBLTDLI' ISRT PAUTSUM0
           (tolerates 'II' = duplicate)
         Until END-ROOT-SEG-FILE = 'Y'
      3. Loop: 3000-READ-CHILD-SEG-FILE → READ INFILE2
         - Extract ROOT-SEG-KEY from child record
         - CALL 'CBLTDLI' GU PAUTSUM0 with qualified SSA
           (position to parent root segment)
         - 3200-INSERT-IMS-CALL: CALL 'CBLTDLI' ISRT PAUTDTL1
           (tolerates 'II' = duplicate)
         Until END-CHILD-SEG-FILE = 'Y'
      4. 4000-FILE-CLOSE: Close both input files
    RC: 0=Success, 16=ABEND (IMS or file I/O failure)

  ═══════════════════════════════════════════════════════════════════
  C5: UNLDGSAM — GSAM-based Unload
  ═══════════════════════════════════════════════════════════════════
  STEP01 - EXEC PGM=DFSRRC00, PARM='DLI,DBUNLDGS,DLIGSAMP'
    PSB: DLIGSAMP (DBPAUTP0 PROCOPT=GOTP + GSAM PCBs for
         PASFLDBD and PADFLDBD)
    INPUTS:
      - DDPAUTP0: OEM.IMS.IMSP.PAUTHDB
      - DDPAUTX0: OEM.IMS.IMSP.PAUTHDBX
    OUTPUTS:
      - PASFILOP: root GSAM (RECFM=F, LRECL=100)
      - PADFILOP: child GSAM (RECFM=F, LRECL=200)
    PROCESSING:
      1. 1000-INITIALIZE: Display start messages
      2. Loop: 2000-FIND-NEXT-AUTH-SUMMARY
         CALL 'CBLTDLI' GN PAUTSUM0
         - 3100-INSERT-PARENT-SEG-GSAM: ISRT via PASFLPCB
         - 3000-FIND-NEXT-AUTH-DTL (GNP PAUTDTL1)
           3200-INSERT-CHILD-SEG-GSAM: ISRT via PADFLPCB
         Until WS-END-OF-ROOT-SEG = 'Y'
      3. 4000-FILE-CLOSE: Display closing message
    RC: 0=Success, 16=ABEND (IMS/GSAM failure)

8.1 Checkpointing Strategy

JobCheckpoint MethodFrequencyCheckpoint ID
C1 (CBPAUP0C)EXEC DLI CHKP (IMS symbolic checkpoint)Every P-CHKP-FREQ summary segments processed (default 5) + final checkpoint at endWK-CHKPT-ID = ‘RMAD’ + 4-digit counter

Gap: Only C1 (purge) implements checkpointing. C3, C4, and C5 have no checkpoint/restart capability. A mid-job failure in C4 (reload) would leave the IMS database in a partially loaded, inconsistent state requiring a full image copy restore.

8.2 Restart Procedures

  • C1 (Purge): Can be restarted from the last IMS checkpoint using /START REGION with CKPTID=RMADnnnn. IMS will backout uncommitted changes and resume from the checkpoint position.
  • C2 (HD Reorg Unload): Restart requires re-running from the beginning. Delete the partial output dataset first.
  • C3 (DLI Unload): Restart from scratch. Delete partial output files (ROOT.FILEO, CHILD.FILEO) and re-run.
  • C4 (Reload): Requires restoring PAUTHDB from image copy before re-running. Partial inserts cannot be easily backed out without IMS log-based recovery.
  • C5 (GSAM Unload): Restart from scratch. GSAM output files should be deleted and re-allocated.

C4 (Reload) is the most time-sensitive due to random GU calls for child segment positioning. For large databases, consider running C3 and C5 in parallel (both are read-only against PAUTHDB) to shorten the overall window.
