Step 1: Menu Dispatch — Resolving the Dynamic XCTL

The Problem: Why Grep Fails

The menu program COMEN01C transfers control using a variable program name — not a literal. No grep for COTRN02C in the calling code will find anything.

* In COMEN01C.cbl (Menu Program) — lines 184-187: EXEC CICS XCTL PROGRAM(CDEMO-MENU-OPT-PGMNAME(WS-OPTION)) COMMAREA(CARDDEMO-COMMAREA) END-EXEC

How Devin Resolves It

Devin reads the data table in COMEN02Y.cpy and the REDEFINES overlay to resolve option 8 = 'COTRN02C':

* In COMEN02Y.cpy — Menu Options Data Table: 10 FILLER PIC 9(02) VALUE 8. 10 FILLER PIC X(35) VALUE 'Transaction Add '. 10 FILLER PIC X(08) VALUE 'COTRN02C'. <-- RESOLVED! 10 FILLER PIC X(01) VALUE 'U'.

Key Insight

The COMMAREA (COCOM01Y.cpy) is the "thread context" of CICS — it carries user ID, source program, and context flags across XCTL boundaries. Without reading this copybook, you cannot understand what state flows between programs.

Step 7: Downstream Batch Processing — CBTRN02C

During the nightly batch cycle, CBTRN02C reads the same TRANSACT file and performs deferred mutations on the Account Master and Category Balance files:

* CBTRN02C.cbl — 2000-POST-TRANSACTION: PERFORM 2700-UPDATE-TCATBAL -- Update category balance PERFORM 2800-UPDATE-ACCOUNT-REC -- Update account balance PERFORM 2900-WRITE-TRANSACTION-FILE -- Write to master * Account balance update: ADD DALYTRAN-AMT TO ACCT-CURR-BAL IF DALYTRAN-AMT >= 0 ADD DALYTRAN-AMT TO ACCT-CURR-CYC-CREDIT ELSE ADD DALYTRAN-AMT TO ACCT-CURR-CYC-DEBIT END-IF REWRITE FD-ACCTFILE-REC FROM ACCOUNT-RECORD

Why This Matters for Modernization

Every dynamic call in this document represents a runtime dependency that must be preserved during migration. Static analysis tools miss these linkages because the program names, dataset names, and parameter bindings are resolved at runtime — not at compile time. Semantic code reading (as demonstrated by Devin) is required to produce accurate call graphs and data lineage maps for mainframe modernization planning.
