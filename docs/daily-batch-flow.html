CardDemo — Daily Batch Flow

Batch operations guide

Main daily batch cycle

The nightly sequence of JCL jobs that takes CardDemo's VSAM files away from CICS, refreshes reference data, posts the day's transactions, calculates interest, backs up and combines transactions, produces statements and hands the files back to the online region.

Overview

CardDemo's online application (CICS) and its batch programs share the same VSAM datasets. Batch jobs cannot update those datasets safely while CICS has them open, so the daily cycle is bracketed by a close and an open of the CICS files. In between it runs these stages:

1. Close CICS filesCLOSEFIL takes TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC away from region CICSAWSA.
2. Refresh VSAM dataIDCAMS jobs delete, define and reload the account, card, cross-reference, customer, transaction and reference files from sample data.
3. Post transactionsPOSTTRAN validates the daily transaction file, posts to the transaction master and updates account and category balances.
4. Calculate interestINTCALC computes interest and fees from the transaction category balance file.
5. Back upTRANBKP copies the transaction master to a new generation of the backup GDG.
6. CombineCOMBTRAN sorts the backup together with system-generated transactions and reloads the master.
7. Produce statementsCREASTMT writes customer statements in text and HTML.
8. Reopen filesTRANIDX rebuilds the alternate index, then OPENFIL gives the files back to CICS.
Source. The sequence follows the "Running Batch Jobs" table in README.md and the submission order in scripts/run_full_batch.sh. Program names come from the EXEC PGM= statements in app/jcl/.

CLOSEFIL / OPENFIL in the JCL. These are usually described as IEFBR14 jobs, but the checked-in app/jcl/CLOSEFIL.jcl and app/jcl/OPENFIL.jcl run PGM=SDSF. They issue /F CICSAWSA,'CEMT SET FIL(...) CLO' (or OPE) for TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC.
TRANBKP runs twice. The same TRANBKP.jcl appears in the refresh group and again after INTCALC. Each run REPROs the transaction KSDS to a new generation AWS.M2.CARDDEMO.TRANSACT.BKUP(+1), deletes the KSDS and its alternate index, and defines an empty KSDS. COMBTRAN then reloads it, and TRANIDX rebuilds the alternate index.

Optional jobs

These jobs belong to optional modules or run on demand. They are not part of the core nightly sequence.

TRANEXTR

Db2: Transaction Type Mgmt

Extracts the latest transaction-type and category data from Db2 with the DSNTIAUL unload utility, run under IKJEFT01. Runs before TRANCATG / TRANTYPE so that those jobs load current data.

app/app-transaction-type-db2/jcl/TRANEXTR.jcl

CBPAUP0J

IMS-DB2-MQ: Pending Authorizations

Purges expired pending authorizations. It runs IMS BMP program CBPAUP0C through DFSRRC00 (PARM='BMP,CBPAUP0C,PSBPAUTB').

app/app-authorization-ims-db2-mq/jcl/CBPAUP0J.jcl

TRANREPT

Submitted from CICS

Transaction report (program CBTRN03C, proc app/proc/TRANREPT.prc). Users request it online from the report screen CORPT00C (transaction CR00). That program writes the job to the JOBS extra-partition TDQ, which submits it to JES.

app/jcl/TRANREPT.jcl

Automation: scripts/run_full_batch.sh

The script submits the whole cycle without manual steps. It checks that an FTP tunnel is listening on local port 2121 and opens tnftp localhost 2121. It switches the FTP session to JES mode with quote site filetype=JES, so each put jcl/<JOB>.jcl submits that member as a batch job instead of storing it as a file.

quote site filetype=JES
put jcl/CLOSEFIL.jcl     # then sleep 5
put jcl/ACCTFILE.jcl     # data refresh ...
put jcl/CARDFILE.jcl
put jcl/XREFFILE.jcl
put jcl/CUSTFILE.jcl
put jcl/TRANBKP.jcl
put jcl/DISCGRP.jcl
put jcl/TCATBALF.jcl
put jcl/TRANTYPE.jcl
put jcl/DUSRSECJ.jcl     # then sleep 5
put jcl/POSTTRAN.jcl     # then sleep 10
put jcl/INTCALC.jcl      # then sleep 5
put jcl/TRANBKP.jcl
put jcl/COMBTRAN.jcl     # then sleep 5
put jcl/TRANIDX.jcl      # then sleep 5
put jcl/OPENFIL.jcl
Differences from the README sequence. The script does not submit TRANCATG or CREASTMT. It loads DISCGRP / TCATBALF / TRANTYPE in a different order from the README. It also uses fixed sleep pauses between submissions and does not check each job's return code, so a failed job does not stop later jobs. Related scripts run_posting.sh and run_interest_calc.sh submit single stages.
