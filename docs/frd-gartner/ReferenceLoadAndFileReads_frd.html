1. Business purpose

Read as Gartner’s client billing and receivables (order-to-cash) estate (assumption A-01), this chain refreshes the reference data that every billable event is classified against. It rebuilds three VSAM files from sequential unloads: the charge types (Research subscription invoice, Conferences registration, Consulting fee, client payment, credit / adjustment; AWS.M2.CARDDEMO.TRANTYPE.VSAM.KSDS), the revenue categories within each charge type, which carry the Research / Conferences / Consulting revenue lines (AWS.M2.CARDDEMO.TRANCATG.VSAM.KSDS), and the open balance per client billing account, charge type and revenue category (AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS). IDCAMS deletes, redefines and reloads each file (app/jcl/TRANTYPE.jcl:22-61, app/jcl/TRANCATG.jcl:22-61, app/jcl/TCATBALF.jcl:22-61).

Later Gartner batch depends on these files. Billable-event posting (POSTTRAN / CBTRN02C) updates the balance-by-category file (app/cbl/CBTRN02C.cbl:57). The month-end late-payment finance charge (INTCALC / CBACT04C) reads it to work out the charge per revenue category on overdue balances (app/cbl/CBACT04C.cbl:28). The billable-event report used by Revenue Accounting (TRANREPT / CBTRN03C) reads the charge-type and revenue-category tables to describe each event (app/cbl/CBTRN03C.cbl:39, :45). If the chain does not run, those jobs use stale or missing codes, and billable events can be reported under the wrong revenue line. If it runs at the wrong time, every open receivable by category that changed since the unload was taken is reset to the unload value. That changes the finance charge a client is billed, the monthly client statement and the receivable balances that feed Gartner’s SEC filings.

After the loads, four read-only listing utilities run one after another: READACCT / CBACT01C (client billing accounts: open receivable, approved client credit line, cash credit limit), READCARD / CBACT02C (research seats: seat ID, subscription term end), READCUST / CBCUS01C (client organizations and contacts) and READXREF / CBACT03C (seat-to-account links). Each reads one master KSDS in key order and prints every record to SYSOUT. READACCT also writes three billing-account extract datasets (app/jcl/READACCT.jcl:37-48). These listings are the estate’s only batch evidence of master-file content after a reload, which makes them candidate SOX 404 control evidence. The whole network sits between a CLOSEFIL job, which closes five CICS files in region CICSAWSA, and an OPENFIL job, which reopens them (app/jcl/CLOSEFIL.jcl:26-30, app/jcl/OPENFIL.jcl:26-30). While the chain runs, Billing & Collections associates cannot use the online screens that need those files.

The OPENFIL job block reads N -- COMP TRIGGERS OTHER JOBS (:138), so the network ends there. No trigger has a condition-code qualifier and no step in any member of the chain codes COND=, so a job is released when its predecessor completes. The only return-code handling is SET MAXCC = 0 after the IDCAMS DELETE (TRANTYPE.jcl:27, TRANCATG.jcl:27, TCATBALF.jcl:27), so a first load with no existing cluster still ends RC 0. Each branch WAITSTEP triggers CLOSEFIL (030) on its own; the listing defines no AND-join (Q-03).
Scheduler sources disagree. This network exists only in CA-7. app/scheduler/CardDemo.controlm has no folder with TRANTYPE, TRANCATG, TCATBALF or any READ* job. For the daily cycle, CA-7 SCHID 030 is CLOSEFIL→CBPAUP0J→POSTTRAN→WAITSTEP→OPENFIL (CardDemo.ca7:43, :70, :97, :124; no TRANBKP anywhere in the file), while Control-M DAILY-TransactionBackup is CLOSEFIL→TRANBKP→WAITSTEP→OPENFIL (CardDemo.controlm:3-25). This FRD documents each source as written and does not assert a combined chain (Q-02). The developer script scripts/run_full_batch.sh uses a third ordering: it submits TCATBALF before TRANTYPE, never submits TRANCATG or any READ* job, and only sleeps between submissions (run_full_batch.sh:35, :38; Q-10).
Job sequence checked against source. The sequence in the Gartner FRD index matches the CA-7 listing at CardDemo.ca7:159-455 job for job, including CLOSEFIL1 / CLOSEFIL2 at the head of each branch (CA-7 JCL MEMBER column = CLOSEFIL, :225, :252). docs/migration/CardDemo_inventory.md:84 draws a different path (OPENFIL → TRANTYPE → (CLOSEFIL1 → TRANCATG | CLOSEFIL2 → TCATBALF) → READACCT) with an OPENFIL→TRANTYPE edge the listing does not have and without the WAITSTEPs; it is wrong (Q-12).

6. Restart, recovery & error handling

6.1 Return-code conventions

RCMeaningDownstream effect
0Normal end of every job. IDCAMS forces it after the DELETE with SET MAXCC = 0 (TRANTYPE.jcl:27), so a missing cluster or a failed delete is hidden. WAITSTEP always ends 0 (MVSWAIT.asm:26).Successor released by the CA-7 completion trigger.
8 / 12IDCAMS DEFINE or REPRO failure in TRANTYPE, TRANCATG or TCATBALF.Not defined in the repo: no trigger has an RC qualifier and no step codes COND= (Q-04).

6.2 Abends

U0999READACCT / CBACT01C, READCARD / CBACT02C, READCUST / CBCUS01C, READXREF / CBACT03COpen, read (other than EOF) or close error; the program displays the error text and file status, then calls CEE3ABD (FR-19).Fix the dataset, rerun the job from the top (READACCT from PREDEL). 6.3 Restart / checkpoint semantics

  • Checkpoint / commit: none. IDCAMS REPRO loads the whole file in one pass, and the READ programs are read-only.
  • Reference load rerun: safe from STEP05 because DELETE / DEFINE / REPRO is a full replace. A failed REPRO leaves the cluster partly loaded; rerun against the same unload. Rerunning TCATBALF after POSTTRAN has posted billable events resets those balances to the unload value, so Finance – Order-to-Cash must approve it.
  • Listing rerun: safe. READACCT PREDEL removes earlier extracts; the other three write only SYSOUT.
  • Files left closed: if any job fails before OPENFIL, the five CICS files stay closed and associates cannot sign on. Rerun the failed job and let the network complete, or submit OPENFIL by hand.
  • Backout: no backup is taken before the delete; the .PS unloads are the only recovery source.

NFR-02Run windowThe online outage runs from CLOSEFIL to OPENFIL and includes four fixed 36 s waits (at least 144 s). The run window must be agreed with Finance – Order-to-Cash so it does not fall in month-end close or on a day when Billing & Collections associates need the online screens.
NFR-03AvailabilityOPENFIL must run (or be run by hand) after any failure, so CICS files are never left closed into the business day (section 6).
NFR-04ConcurrencyTRANCATG and TCATBALF run in parallel. No job may update TCATBALF (POSTTRAN, INTCALC) while it is being reloaded; the legacy chain relies on the CICS close and on scheduling to achieve this.
NFR-05IdempotencyEach reference load is a full replace and gives the same result when rerun against the same unload. The listings are read-only.
NFR-06Data integrity (SOX 404)Gartner is an SEC registrant that files 10-K and 10-Q reports, so management assesses internal control over financial reporting under SOX Section 404. The charge-type, revenue-category and balance-by-category files feed posted receivables and finance charges, so a reload is a change to financially significant reference data. Required controls: approved unload source, record count reconciled between the .PS unload and the loaded KSDS, and the listings kept as evidence.
NFR-07Revenue (ASC 606)Billable events are classified by charge type and revenue category. Those codes drive how revenue is broken down into the Research (subscription, recognized ratably over the term), Conferences and Consulting revenue lines. Any change to TRANTYPE / TRANCATG content needs Finance – Revenue Accounting sign-off before it is loaded.
NFR-08Payment data (PCI DSS v4.0)The seat record carries a 16-digit CARD-NUM and a CARD-CVV-CD (CVACT02Y.cpy:5-7), and CBACT02C / CBACT03C print them in clear text. Until Information Security confirms the field holds no real PANs, treat it as cardholder data: Req. 3.3.1.2 (no card verification code kept after authorization), Req. 3.4.1 (mask PAN when displayed) and Req. 3.5.1 (render PAN unreadable where stored) apply to SYSOUT and extracts.
NFR-09Client PII (GDPR / UK GDPR, CCPA/CPRA)CBCUS01C prints client contact names, addresses, phone numbers, CUST-SSN, government-issued ID and date of birth (CVCUS01Y.cpy:4-23). For EU / UK client contacts, GDPR Art. 5(1)(c) data minimization and Art. 32 security apply; for California residents, SSN and government ID are sensitive personal information under CCPA/CPRA. The target listing must mask or omit these fields.
NFR-10Retention & auditKeep job logs, listings and reload evidence for the period set by the Gartner records-retention policy (assumption A-04); limit access to SYSOUT that holds PII or card data.
NFR-11ResilienceKeep the .PS unloads until the next successful reload so a failed REPRO can be rerun (section 6).
