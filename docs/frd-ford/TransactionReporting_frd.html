1. Business purpose

TransactionReporting produces CardDemo's two printed views of posted card activity. The Daily Transaction Report (program CBTRN03C) lists every posted transaction whose processing date falls inside a requested range, grouped by card, with account, page and grand totals. An operator requests it from the CICS screen CR00 (program CORPT00C, app/csd/CARDDEMO.CSD:409-410): the program builds a 17-card JCL deck for job TRNRPT00 (app/cbl/CORPT00C.cbl:81-125) and writes it to the extra-partition transient data queue JOBS, whose DD INREADER feeds the JES internal reader (app/csd/CARDDEMO.CSD:499-503). The category-balance print (PRTCATBL) unloads the TCATBALF VSAM file maintained by posting and writes a sorted, edited listing of the balance per account / transaction type / category (app/jcl/PRTCATBL.jcl:21-63). CA-7 runs it in a CLOSEFIL → PRTCATBL → WAITSTEP → OPENFIL bracket that takes five CICS files offline while batch runs (app/scheduler/CardDemo.ca7:529-571).

If the chain does not run, no transaction report exists for the requested period (the CR00 user still sees ... report submitted for printing ..., because the screen does not wait for the job), and the day's category-balance listing is missing. A failure between CLOSEFIL and OPENFIL leaves TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC closed to CICS, which blocks sign-on (USRSEC) and the account/transaction screens until OPENFIL is run by hand (app/jcl/OPENFIL.jcl:26-30).

Business capabilityHow this stream serves it
Operational reporting of posted card transactions for a periodCR00 offers the current month, the current year or a custom date range (app/cbl/CORPT00C.cbl:212-256); TRANREPT unloads, filters and sorts TRANSACT, and CBTRN03C formats a 133-byte print report with totals (app/proc/TRANREPT.prc:21-78).
Category-level balance oversightPRTCATBL unloads TCATBALF and prints the balance per account, type and category, sorted on the full key (app/jcl/PRTCATBL.jcl:29-63).
Online / batch file integrityCLOSEFIL and OPENFIL run PGM=SDSF and issue CEMT SET FIL(...) CLO/OPE on region CICSAWSA (app/jcl/CLOSEFIL.jcl:22-30, app/jcl/OPENFIL.jcl:22-30); WAITSTEP adds a 36-second pause before files reopen (app/jcl/WAITSTEP.jcl:22-26).
Operator self-service (online to batch)The internal-reader hand-off means no scheduler entry is needed for TRANREPT; the JCL and its date parameters are generated at request time (app/cbl/CORPT00C.cbl:462-510).

Gating conditions: Trigger A. No scheduler releases TRANREPT: TRANREPT and TRNRPT00 appear in neither CardDemo.ca7 nor CardDemo.controlm. The job exists only once CORPT00C has validated the request, the operator has typed Y/y in CONFIRM, and every card up to /*EOF has been written to TDQ JOBS with DFHRESP(NORMAL) (app/cbl/CORPT00C.cbl:464-508, :525-535). Inside the job no step carries COND= (app/proc/TRANREPT.prc:21,35,57); the gate between steps is dataset allocation of the (+1) generation the previous step should have created. Trigger B. CA-7 uses completion triggers only, each with QTM=0100 LEADTM=0000 SUBMTM=0000: OPENFIL of SCHID=030 triggers CLOSEFIL SCHID=031 (CardDemo.ca7:529-532); CLOSEFIL triggers PRTCATBL SCHID=031 (:534-537); PRTCATBL triggers WAITSTEP SCHID=031 (:563-564); WAITSTEP triggers OPENFIL SCHID=031 (:566-569); the OPENFIL block at :571 lists no triggered jobs. No CA-7 requirement and no Control-M IN/OUT condition exists for this network (PRTCATBL/TCATBALF/TRANREPT have zero matches in CardDemo.controlm), and PRTCATBL's three steps have no COND= (app/jcl/PRTCATBL.jcl:21,29,43). Scheduler disagreement (not asserted as a chain): CA-7 SCHID=030 daily is CLOSEFIL → CBPAUP0J → POSTTRAN → WAITSTEP → OPENFIL with no TRANBKP (CardDemo.ca7:18-126); Control-M DAILY-TransactionBackup is CLOSEFIL → TRANBKP → WAITSTEP → OPENFIL via OUTCOND/INCOND pairs (CardDemo.controlm:3-25). This FRD documents each source as written; see Q-01.

6.3 Restart / checkpoint semantics

There are no checkpoints or commit points anywhere in the chain. CBTRN03C is a single pass over a sequential extract with no restart key (app/cbl/CBTRN03C.cbl:170-206); the unit of restart is the whole job. Every output is either a new GDG generation (DISP=(NEW,CATLG,DELETE), app/proc/TRANREPT.prc:27,49,74; app/jcl/PRTCATBL.jcl:35) or a dataset that is deleted first (TCATBALF.REPT, app/jcl/PRTCATBL.jcl:21-25), so a cold rerun is always safe and needs no backout; a rerun simply adds another generation. The job name TRNRPT00 is fixed in CORPT00C (app/cbl/CORPT00C.cbl:83-84); whether two concurrent requests run side by side or are serialized depends on the JES duplicate-job-name setting, which is not in the repo (assumption Q-22). For trigger B, if PRTCATBL or WAITSTEP fails the five CICS files stay closed until OPENFIL is submitted by hand (app/jcl/OPENFIL.jcl:26-30); CA-7 does not release it because the trigger chain is broken (app/scheduler/CardDemo.ca7:563-569).
