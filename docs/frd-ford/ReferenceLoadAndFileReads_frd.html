1. Business purpose

The chain rebuilds the three VSAM reference files that the rest of the CardDemo batch estate reads: the transaction-type table (AWS.M2.CARDDEMO.TRANTYPE.VSAM.KSDS), the transaction-category table (AWS.M2.CARDDEMO.TRANCATG.VSAM.KSDS) and the per-account transaction-category balance file (AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS). Each one is deleted, redefined and reloaded by IDCAMS from a sequential unload (app/jcl/TRANTYPE.jcl:22-61, app/jcl/TRANCATG.jcl:22-61, app/jcl/TCATBALF.jcl:22-61). Posting (POSTTRAN / CBTRN02C, app/cbl/CBTRN02C.cbl:57), interest calculation (INTCALC / CBACT04C, app/cbl/CBACT04C.cbl:28) and the transaction report (TRANREPT / CBTRN03C, app/cbl/CBTRN03C.cbl:39, :45) read these files. If the chain does not run, those jobs work from stale or missing reference data, and every category balance changed since the last load is kept rather than reset.

After the loads, four read-only utilities run in sequence: READACCT / CBACT01C, READCARD / CBACT02C, READCUST / CBCUS01C and READXREF / CBACT03C. Each reads one master KSDS in key order and prints every record to SYSOUT. READACCT also writes three account extract datasets (app/jcl/READACCT.jcl:37-48). These prints are the estate's only batch evidence of master-file content after a load. The whole network sits between a CLOSEFIL job that closes five CICS files in region CICSAWSA and an OPENFIL job that reopens them (app/jcl/CLOSEFIL.jcl:26-30, app/jcl/OPENFIL.jcl:26-30). Online users cannot use those files while the chain runs.

Business capabilityHow this stream serves it
Transaction reference data (types and categories)TRANTYPE and TRANCATG fully replace the type and category tables (app/cpy/CVTRA03Y.cpy, app/cpy/CVTRA04Y.cpy) that TRANREPT / CBTRN03C uses to describe transactions.
Account category-balance seedingTCATBALF fully replaces the per-account / type / category balance file (app/cpy/CVTRA01Y.cpy) that POSTTRAN / CBTRN02C updates and INTCALC / CBACT04C reads.
Operational verification of master filesREADACCT, READCARD, READCUST, READXREF print every account, card, customer and card cross-reference record.
Account extractsREADACCT writes fixed (107-byte), array (110-byte) and variable-length (12 / 39-byte) account extracts (app/cbl/CBACT01C.cbl:56-85).
Online / batch file isolationCLOSEFIL / OPENFIL quiesce and release CICS files TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC around the batch work.

Correction to the FRD index sequence. The index lists CLOSEFIL → TRANTYPE → { TRANCATG | TCATBALF } → READACCT → …. 6. Restart, recovery & error handling

6.1 Return-code conventions

RCMeaningDownstream effect
0IDCAMS: all commands succeeded, or a failed DELETE was reset by SET MAXCC = 0 (TRANTYPE.jcl:27). COBOL utilities: reached GOBACK after EOF (CBACT01C.cbl:160). COBSWAIT: always (MVSWAIT.asm:26).CA-7 trigger fires; successor queued (QTM=0100).
8 / 12IDCAMS DEFINE or REPRO failure (catalog conflict, volume AWSHJ1 unavailable, duplicate key, missing unload). No step tests these codes.Not defined in repo whether CA-7 treats this as completion. If it does, the empty or partial cluster is used by later jobs (Q-05).
U0999COBOL utility abend via CEE3ABD after any open, read, close or write failure.Job ends abnormally; successor not triggered; CICS files stay closed until OPENFIL is run.
(none)SDSF step in CLOSEFIL / OPENFIL: MODIFY commands are issued, but the CEMT result is not returned as the step RC.A failed close is invisible to the scheduler; loads run while CICS may still hold the files (Q-06).

6.3 Restart / checkpoint semantics

There are no checkpoints, commit intervals or restart keys in the chain. Every job is a cold full rerun: the three loads delete and redefine their cluster (TRANTYPE.jcl:22-49), READACCT pre-deletes its outputs (READACCT.jcl:22-28), the other reads are read-only, CLOSEFIL / OPENFIL issue idempotent CEMT commands, and WAITSTEP is stateless. CA-7 records # OF TIMES RESTARTED = 0000 for every job (e.g. CardDemo.ca7:40). After a mid-chain failure, operations must either rerun from the failed job or run OPENFIL by hand to give the files back to CICS.
