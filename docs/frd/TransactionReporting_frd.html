1. Business purpose

TransactionReporting produces the two printed views of posted card activity that CardDemo offers. The Daily Transaction Report (TRANREPT, program CBTRN03C) lists every posted transaction whose processing date falls in a requested range, grouped by card with account, page and grand totals; it is requested by an operator from the CICS screen CR00 (CORPT00C), which builds a JCL deck and hands it to JES through the extra-partition transient data queue JOBS (app/csd/CARDDEMO.CSD:499-503). The category-balance print (PRTCATBL) unloads the TCATBALF VSAM file maintained by posting and writes a sorted, edited listing of balance per account / transaction type / category; CA-7 runs it inside a CLOSEFIL → PRTCATBL → WAITSTEP → OPENFIL bracket that takes the CICS files offline while batch reads them (app/scheduler/CardDemo.ca7:529-571).

If the chain does not run, no transaction report is produced for the requested period (the CR00 user receives a "submitted" message but no output), and the category balance listing for the day is missing; because CLOSEFIL/OPENFIL bracket the print, a failure between them leaves TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC closed to CICS until OPENFIL is run by hand (app/jcl/OPENFIL.jcl:26-30).

Business capabilityHow this stream serves it
Operational reporting of posted card transactions for a periodCR00 lets an operator ask for the current month, current year or a custom date range (app/cbl/CORPT00C.cbl:212-256); TRANREPT extracts, filters and sorts TRANSACT and CBTRN03C formats a 133-byte print report with totals (app/proc/TRANREPT.prc:21-78).
Category-level balance oversightPRTCATBL unloads TCATBALF and prints balance per account, type and category, sorted on the full key (app/jcl/PRTCATBL.jcl:29-63).
Online / batch file integrityCLOSEFIL and OPENFIL issue CEMT SET FIL ... CLO/OPE to region CICSAWSA so batch can take the VSAM files while CICS is quiesced; WAITSTEP inserts a 36 s pause (app/jcl/CLOSEFIL.jcl:26-30, app/jcl/WAITSTEP.jcl:22-26).
Operator self-service (online to batch)The internal reader hand-off means no scheduler entry is needed for TRANREPT; the JCL and its date parameters are generated at request time (app/cbl/CORPT00C.cbl:81-125, :498-523).

Gating conditions: (a) No scheduler releases TRANREPT: TRANREPT appears in neither CardDemo.ca7 nor CardDemo.controlm. The job is released when CORPT00C has validated the request, the operator has typed Y in the confirm field, and all deck lines have been written to TDQ JOBS with DFHRESP(NORMAL) (app/cbl/CORPT00C.cbl:464-508, :525-535). Inside the job there is no COND= on any step (app/proc/TRANREPT.prc:21,35,57), so SORT and CBTRN03C run regardless of the REPRO return code; CBTRN03C itself abends on any non-zero file status. (b) CA-7 uses completion triggers only: OPENFIL (end of the SCHID=030 CREASTMT → TXT2PDF1 network) triggers CLOSEFIL SCHID=031 (CardDemo.ca7:529-532); CLOSEFIL triggers PRTCATBL SCHID=031 (:534-537); PRTCATBL triggers WAITSTEP SCHID=031 (:563-564); WAITSTEP triggers OPENFIL SCHID=031 (:566-569), whose LJOB block lists no triggered jobs (:571), so the network ends there. All triggers carry QTM=0100 LEADTM=0000 SUBMTM=0000; no CA-7 requirement (RQMT) or COND= code gates any step, and PRTCATBL's three steps have no COND= either (app/jcl/PRTCATBL.jcl:21,29,43). Estate gotcha: the two scheduler sources disagree on the daily chain. CA-7 SCHID=030 is CLOSEFIL → CBPAUP0J → POSTTRAN → WAITSTEP → OPENFIL (no TRANBKP, CardDemo.ca7:40-126); Control-M DAILY-TransactionBackup is CLOSEFIL → TRANBKP → WAITSTEP → OPENFIL (no POSTTRAN, CardDemo.controlm:3-25). This FRD does not assert a combined daily chain; the PRTCATBL network exists only in CA-7 (zero matches for PRTCATBL/TRANREPT/TCATBALF in CardDemo.controlm). Note also that CA-7 reuses SCHID=031 for the unrelated CLOSEFIL1 → TRANCATG → WAITSTEP segment (CardDemo.ca7:216-298); see Q-03.

6.3 Restart / checkpoint semantics

There are no checkpoints or commit points anywhere in the chain. CBTRN03C is a single pass over a sequential extract with no restart key (app/cbl/CBTRN03C.cbl:170-206); the unit of restart is the whole job. Because every output is either a new GDG generation (DISP=(NEW,CATLG,DELETE), app/proc/TRANREPT.prc:27,49,74; app/jcl/PRTCATBL.jcl:35) or a dataset deleted first (TCATBALF.REPT, app/jcl/PRTCATBL.jcl:21-25), a cold rerun is always safe and needs no backout. A rerun of TRANREPT on the same day simply produces another generation; the job name TRNRPT00 is fixed in CORPT00C (app/cbl/CORPT00C.cbl:83-84), so concurrent requests queue in JES by name. For trigger (b), if PRTCATBL or WAITSTEP fails the CICS files remain closed until OPENFIL is submitted manually (app/jcl/OPENFIL.jcl:26-30); CA-7 will not auto-release it because the trigger chain is broken (app/scheduler/CardDemo.ca7:563-569).
