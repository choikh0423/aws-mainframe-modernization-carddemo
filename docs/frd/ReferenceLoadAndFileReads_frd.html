1. Business purpose

The chain rebuilds the three VSAM reference files that the rest of the CardDemo batch estate reads but never writes: the transaction-type table (AWS.M2.CARDDEMO.TRANTYPE.VSAM.KSDS), the transaction-category table (TRANCATG.VSAM.KSDS) and the per-account transaction-category balance file (TCATBALF.VSAM.KSDS). Each is dropped, redefined and reloaded by IDCAMS from a sequential unload (app/jcl/TRANTYPE.jcl:22-61, TRANCATG.jcl:22-61, TCATBALF.jcl:22-61). Posting (POSTTRAN/CBTRN02C, app/cbl/CBTRN02C.cbl:57), interest calculation (INTCALC/CBACT04C, app/cbl/CBACT04C.cbl:28) and transaction reporting (TRANREPT/CBTRN03C, app/cbl/CBTRN03C.cbl:39,45) read these files; if the chain does not run, those jobs work against stale or missing reference data.

After the loads, four read-only utilities (READACCT/CBACT01C, READCARD/CBACT02C, READCUST/CBCUS01C, READXREF/CBACT03C) read the account, card, customer and card-cross-reference master files sequentially and print every record to SYSOUT; READACCT additionally writes three extract datasets (app/jcl/READACCT.jcl:37-48). They are the estate's only batch evidence of master-file content and are used to verify the files after a load. The whole network sits between a CLOSEFIL job that closes five CICS files in region CICSAWSA and an OPENFIL job that reopens them (app/jcl/CLOSEFIL.jcl:26-30, app/jcl/OPENFIL.jcl:26-30), so online users lose access to transactions, cross-reference, account and user-security files for the duration of the chain.

Business capabilityHow this stream serves it
Transaction reference data (types and categories)TRANTYPE and TRANCATG replace the VSAM tables used to classify and describe transactions (app/cpy/CVTRA03Y.cpy, CVTRA04Y.cpy) consumed by TRANREPT/CBTRN03C.
Account category balance seedingTCATBALF replaces the per-account/type/category balance file (app/cpy/CVTRA01Y.cpy) that POSTTRAN/CBTRN02C updates and INTCALC/CBACT04C reads.
Operational verification and extractsREADACCT/READCARD/READCUST/READXREF print every master record; READACCT also produces fixed, array and variable-length account extracts (app/cbl/CBACT01C.cbl:56-85).
Online availability controlCLOSEFIL/OPENFIL quiesce and release the CICS files TRANSACT, CCXREF, ACCTDAT, CXACAIX, USRSEC around the batch work.

6.3 Restart / checkpoint semantics

There are no checkpoints, commit intervals or restart keys anywhere in the chain. Every job is a cold full rerun: the three loads delete and redefine their cluster (TRANTYPE.jcl:22-49), READACCT pre-deletes its outputs (READACCT.jcl:22-28), the other reads are read-only, CLOSEFIL/OPENFIL issue idempotent CEMT commands, and WAITSTEP is stateless. CA-7 records "# OF TIMES RESTARTED = 0000" for every job (CardDemo.ca7:186 and the equivalent line in each block). Restart therefore means resubmitting the failed job and letting the triggers continue. Two consequences follow: (a) if a branch job fails, the other branch's WAITSTEP still triggers CLOSEFIL (030) (ca7:303, 335), and whether the read jobs then run before the failed branch is repaired depends on CA-7 requirement definitions that are not in the listing (Q-03); (b) if any job between CLOSEFIL and OPENFIL abends, the five CICS files remain closed until OPENFIL is run by hand. No backout job exists; a bad reference load is corrected by re-running the load with a corrected unload.
