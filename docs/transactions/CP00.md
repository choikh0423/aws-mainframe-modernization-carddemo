## 4. Purpose / Description

Background (non-terminal) transaction started by the MQ trigger monitor when authorization requests arrive. It reads requests from the queue in a loop (5 second wait), looks up the card (`CCXREF`), account (`ACCTDAT`) and customer (`CUSTDAT`), approves or declines based on available credit (credit limit minus balance), writes the response to the reply queue named in the request, and inserts / updates the summary (`PAUTSUM0`) and detail (`PAUTDTL1`) segments in IMS.

## 10. Error handling

| Condition | Detection | Behaviour / message |
|:--|:--|:--|
| NOTFND | `DFHRESP(NOTFND)` | Record not found: message shown, key field highlighted |
| Any other CICS response | `RESP` / `RESP2` not handled above | Generic "unable to ..." message with the response code |
| Card not in `CCXREF` / account or customer not found | `DFHRESP(NOTFND)` | Request declined with a reason code; error logged to `CSSL` |
| Amount greater than available credit | `WS-TRANSACTION-AMT > WS-AVAILABLE-AMT` | Declined: response code `05`, reason `4100` (insufficient funds). Approved responses use `00` |
| Other decline reasons | Reason codes in `COPAUA0C` | `3100` record not found, `4200` card not active, `4300` account closed, `5100` card fraud, `5200` merchant fraud |
