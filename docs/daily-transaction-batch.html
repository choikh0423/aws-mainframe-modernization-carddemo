1. Overview

The DAILY-TransactionBackup folder in app/scheduler/CardDemo.controlm (line 3) holds four jobs that run once a day, one after the other. Together they take a backup of the transaction master file while CICS is not using it.

  1. CLOSEFIL: take the CICS files offline. Sends CEMT SET FIL(...) CLO to the CICS region CICSAWSA for the five CardDemo files (TRANSACT, CCXREF, ACCTDAT, CXACAIX, USRSEC). After this, batch jobs can take exclusive control of the VSAM clusters.
  2. TRANBKP: back up the transactions. Copies AWS.M2.CARDDEMO.TRANSACT.VSAM.KSDS into a new generation of the GDG AWS.M2.CARDDEMO.TRANSACT.BKUP(+1). It then deletes the KSDS and its alternate index and defines a new, empty KSDS (app/jcl/TRANBKP.jcl).
  3. WAITSTEP: pace the chain. Runs COBSWAIT with 00003600 centiseconds (36 seconds) so the catalog changes settle before CICS reopens the files.
  4. OPENFIL: reopen the files. Sends CEMT SET FIL(...) OPE for the same five files, so online users can get to them again.

The jobs are not triggered directly. Each one adds a Control-M condition (OUTCOND SIGN="+") that the next job waits for (INCOND). The next job then deletes that condition (OUTCOND SIGN="-") so it cannot fire twice. Every condition is named DAILY-TransactionBackup-<JOB> and dated ODATE="ODAT", which scopes it to the current order date.

2. Flow diagram

Control-M order of execution. Each arrow is a prerequisite condition: the job above adds it (+) and the job below needs it and then deletes it (−).

At the end of TRANBKP the day's transactions exist only in the newest TRANSACT.BKUP generation. TRANSACT.VSAM.KSDS is empty, and the alternate index TRANSACT.VSAM.AIX (and its path) is gone. This job does not rebuild them. app/jcl/TRANIDX.jcl does that, and it is not part of this folder.

10. CA-7 cross-reference

app/scheduler/CardDemo.ca7 is a CA-7 LJOB,LIST=ALL listing. Jobs are linked by TRIGGERED JOBS entries under a schedule ID (SCHID), not by named conditions. All jobs belong to system CARDDEMO and use JCLLIB=&CARDDEMOPRODJCL.

TRANBKP does not appear anywhere in the CA-7 listing. The four jobs in this folder do appear, but CA-7 uses CLOSEFIL/WAITSTEP/OPENFIL as bracket jobs around other work:

The CA-7 network nearest to this folder is the SCHID=030 posting segment at the top of the listing (lines 18-132):

CA-7 SCHID=030   CLOSEFIL → CBPAUP0J → POSTTRAN → WAITSTEP → OPENFIL
Control-M        CLOSEFIL → TRANBKP  →            WAITSTEP → OPENFIL   (DAILY-TransactionBackup)

Scheduler mismatch. The two scheduler sources describe different daily work. Control-M backs up and resets the transaction master between the close and open bracket. CA-7 purges expired authorizations and posts transactions (CBPAUP0J, POSTTRAN) in the same position, and never runs TRANBKP. Neither file shows the two chains running together. Check with the scheduling owners before assuming a combined order such as POSTTRAN then TRANBKP. Note that README's "Running Batch Jobs" list puts TRANBKP after POSTTRAN/INTCALC, but that is a manual run order and not either scheduler.

11. Observations

  • A failed backup can still delete the master. STEP05 (DELETE) has no COND parameter, so it still runs if STEP05R (REPRO) ends with a non-zero return code without abending. In that case TRANSACT.VSAM.KSDS is deleted even though BKUP(+1) was not written cleanly. Only STEP10 is protected (COND=(4,LT)), and STEP05 sets MAXCC back to 0 when its result is 8 or less.
  • The transaction file goes back online empty and without its AIX. OPENFIL reopens TRANSACT right after it is redefined. TRANSACT.VSAM.AIX is deleted but no job in this folder runs TRANIDX. Anything that reads the transaction AIX/path will find it missing until TRANIDX runs.
  • More files are closed than are changed. CLOSEFIL/OPENFIL close and reopen five files, but TRANBKP only changes TRANSACT. CCXREF, ACCTDAT, CXACAIX and USRSEC (including sign-on security) are unavailable to CICS for the whole chain anyway.
  • README says something different about the programs. The README application table lists CLOSEFIL/OPENFIL as IEFBR14. The JCL actually runs PGM=SDSF and sends CEMT commands.
  • The pacing is fixed. WAITSTEP always waits 36 seconds. It does not check that the catalog or the CICS region is in any particular state.
