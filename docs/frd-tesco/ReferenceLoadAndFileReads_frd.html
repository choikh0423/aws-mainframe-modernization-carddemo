1. Business purpose

For the Tesco Bank Clubcard Credit Card platform, this chain refreshes the reference data that every card transaction is classified against. It rebuilds three VSAM files from sequential unloads: the transaction type codes (purchase, cash, payment, refund and so on; AWS.M2.CARDDEMO.TRANTYPE.VSAM.KSDS), the transaction category codes within each type (AWS.M2.CARDDEMO.TRANCATG.VSAM.KSDS) and the cardholder balance-by-category file, one balance per credit card account, type and category (AWS.M2.CARDDEMO.TCATBALF.VSAM.KSDS). IDCAMS deletes, redefines and reloads each file (app/jcl/TRANTYPE.jcl:22-61, app/jcl/TRANCATG.jcl:22-61, app/jcl/TCATBALF.jcl:22-61).

Later overnight batch depends on these files. Card transaction posting (POSTTRAN / CBTRN02C) updates the balance-by-category file (app/cbl/CBTRN02C.cbl:57). The monthly interest charge (INTCALC / CBACT04C) reads it to work out interest per category (app/cbl/CBACT04C.cbl:28). The transaction report (TRANREPT / CBTRN03C) reads the type and category tables to describe each transaction (app/cbl/CBTRN03C.cbl:39, :45). If the chain does not run, those jobs use stale or missing codes. If it runs at the wrong time, every balance by category changed since the unload was taken is reset to the unload value. That changes the interest a cardholder is charged, and so what the monthly card statement shows.

After the loads, four read-only listing utilities run one after another: READACCT / CBACT01C (credit card accounts: balance, credit limit, cash limit), READCARD / CBACT02C (Clubcard Credit Card plastics), READCUST / CBCUS01C (cardholders) and READXREF / CBACT03C (card-to-account-to-customer links). Each reads one master KSDS in key order and prints every record to SYSOUT. READACCT also writes three account extract datasets (app/jcl/READACCT.jcl:37-48). These listings are the estate's only batch evidence of master-file content after a reload. The whole network sits between a CLOSEFIL job, which closes five CICS files in region CICSAWSA, and an OPENFIL job, which reopens them (app/jcl/CLOSEFIL.jcl:26-30, app/jcl/OPENFIL.jcl:26-30). While the chain runs, colleagues cannot use the online card-servicing screens that need those files.

Business capabilityHow this stream serves it
Transaction type & category codesTRANTYPE and TRANCATG fully replace the type and category tables (app/cpy/CVTRA03Y.cpy, app/cpy/CVTRA04Y.cpy) that TRANREPT / CBTRN03C uses to describe card transactions.
Balance by category (purchase / cash / balance transfer, assumed)TCATBALF fully replaces the per-account / type / category balance file (app/cpy/CVTRA01Y.cpy) that POSTTRAN updates and INTCALC uses for the monthly interest charge.

Online / batch file isolationCLOSEFIL / OPENFIL quiesce and release CICS files TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC around the batch work.

The OPENFIL job block reads N -- COMP TRIGGERS OTHER JOBS (:138), so the network ends there. No trigger has a condition-code qualifier, and no step in any member of the chain codes COND=, so a job is released when its predecessor completes. The only return-code handling is SET MAXCC = 0 after the IDCAMS DELETE (TRANTYPE.jcl:27, TRANCATG.jcl:27, TCATBALF.jcl:27), so a first load with no existing cluster still ends RC 0. Each branch WAITSTEP triggers CLOSEFIL (030) on its own; the listing defines no AND-join (Q-03).
Scheduler sources disagree. This network exists only in CA-7. app/scheduler/CardDemo.controlm has no folder with TRANTYPE, TRANCATG, TCATBALF or any READ* job. For the daily cycle, CA-7 SCHID 030 is CLOSEFIL→CBPAUP0J→POSTTRAN→WAITSTEP→OPENFIL (CardDemo.ca7:43, :70, :97, :124; no TRANBKP anywhere in the file), while Control-M DAILY-TransactionBackup is CLOSEFIL→TRANBKP→WAITSTEP→OPENFIL (CardDemo.controlm:3-25). This FRD documents each source as written and does not assert a combined chain (Q-02). The developer script scripts/run_full_batch.sh uses a third ordering: it submits TCATBALF before TRANTYPE, never submits TRANCATG or any READ* job, and only sleeps between submissions (run_full_batch.sh:35, :38; Q-10).
Job sequence checked against source. The sequence in the FRD index (CLOSEFIL → TRANTYPE → WAITSTEP → { CLOSEFIL1 → TRANCATG → WAITSTEP | CLOSEFIL2 → TCATBALF → WAITSTEP } → CLOSEFIL → READACCT → READCARD → READCUST → READXREF → WAITSTEP → OPENFIL) matches the CA-7 listing at CardDemo.ca7:159-455 job for job. docs/migration/CardDemo_inventory.md:84 draws a different path (OPENFIL → TRANTYPE → (CLOSEFIL1 → TRANCATG | CLOSEFIL2 → TCATBALF) → READACCT), with an OPENFIL→TRANTYPE edge that the listing does not have and without the WAITSTEPs. It is wrong (Q-12).

FR-03Each reference load is a full replace: STEP05 deletes the cluster and forces MAXCC 0, STEP10 redefines it, STEP15 REPROs the whole sequential unload into it. Records left from an earlier load must not survive.app/jcl/TRANTYPE.jcl:22-61; TRANCATG.jcl:22-61; TCATBALF.jcl:22-61Load a 7-record TRANTYPE.PS over a cluster holding 9 records: the cluster holds exactly 7. FR-04The clusters are defined as: TRANTYPE KEYS(2 0) RECORDSIZE(60 60) SHAREOPTIONS(1 4); TRANCATG KEYS(6 0) RECORDSIZE(60 60) SHAREOPTIONS(2 3); TCATBALF KEYS(17 0) RECORDSIZE(50 50) SHAREOPTIONS(2 3); all ERASE INDEXED.TRANTYPE.jcl:40-44; TRANCATG.jcl:40-42; TCATBALF.jcl:40-42LISTCAT after the load shows the stated key length, LRECL and SHROPTNS (compare app/catlg/LISTCAT.txt:3781).

The step ends RC 0.COBSWAIT / PROCEDURE DIVISION (COBSWAIT.cbl:36-38); MVSWAIT.asm:23, :26; ASMWAIT.mac:19A WAITSTEP run with the shipped card lasts 36 s (±1 s) and ends RC 0; 00000000 returns at once.

6. Restart, recovery & error handling

6.1 Return-code conventions

RCMeaningDownstream effect
0Normal completion. For IDCAMS STEP05 it is forced by SET MAXCC = 0 even when the DELETE fails because the cluster does not exist. WAITSTEP always returns 0 (MVSWAIT.asm:26).CA-7 releases the successor.
4 / 8 / 12 (IDCAMS STEP10 / STEP15)DEFINE or REPRO failure: for example a duplicate name, no space on AWSHJ1, a missing input or key-sequence errors.No COND= in the members, so later steps in the job still run. The scheduler gate is not defined (Q-04).

6.3 Restart / checkpoint semantics

No job has checkpoints or a commit interval. Every job restarts from its first step. The reference loads are idempotent because STEP05 deletes the cluster: rerunning TRANTYPE, TRANCATG or TCATBALF rebuilds the file from the same unload. Restarting STEP15 on its own after a partial REPRO is not supported, because the cluster may hold some records; rerun from STEP05. TCATBALF holds running balances that POSTTRAN updates (CBTRN02C.cbl:57). Once posting has run, a TCATBALF rerun from the original unload loses those updates, so a backup of the cluster must be taken before a TCATBALF rerun, or the rerun must be limited to a cold start (Q-08). CLOSEFIL, OPENFIL and WAITSTEP can be rerun any number of times. READACCT is idempotent because of PREDEL. READCARD, READCUST and READXREF write only SYSOUT.

NFR-01VolumeShipped volumes: transaction types 7, categories 18, balance-by-category 50, accounts 50, cards 50, cardholders 50, card links 50 (ASCII unloads in app/data/ASCII; the EBCDIC unload sizes agree). NFR-04ConcurrencyBranches 031 and 032 may run in parallel. TCATBALF must not run while POSTTRAN or INTCALC is using the balance-by-category file; neither scheduler export enforces this (Q-11).
NFR-05IdempotencyEvery job must be safe to rerun from its first step (section 6.3), except that a TCATBALF rerun after posting loses balance updates.
NFR-06Data integrityBalance-by-category values feed the monthly interest charge (CBACT04C.cbl:28) and so the monthly card statement. Any reload must be reconciled (record count and balance total, unload against cluster) so that statements stay accurate for CCA 1974 s.78(4) and CONC, and cardholders get correct information under Consumer Duty (PRIN 2A consumer understanding outcome). No reconciliation exists in source.
NFR-07Retention / auditSYSOUT listings and READACCT extracts are the only evidence of master-file content after a reload. Keep them as records under SYSC 9 for the period set by Finance & Regulatory Reporting; MSGCLASS / SYSOUT retention is not defined in source (Q-15).
NFR-08ResilienceFull-replace loads with no backup step mean a failed STEP15 leaves an empty or partial cluster. Recovery needs the unload to be kept until the network ends (PRA SS1/21 recovery within tolerance).
