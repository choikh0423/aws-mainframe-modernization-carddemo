1. Business purpose

MonthlyInterestCalculation is the month-end interest run for the Tesco Bank Clubcard Credit Card portfolio. Once a month it charges interest on every credit card account and records each charge as a card transaction so that it appears on the cardholder's monthly card statement.

In order: CLOSEFIL asks the CICS region to release the online files so that batch has them to itself. INTCALC runs the COBOL program CBACT04C, which reads every balance by category (TCATBALF; purchase / cash / balance transfer is the assumed Tesco reading of the type and category codes) in account order. For each balance it finds the account's interest-rate (APR) pricing group in DISCGRP, falling back to the DEFAULT group, and computes balance × rate ÷ 1200. Each charge becomes one card transaction written by the system to a new SYSTRAN generation. The account's total charge is added to the credit card account balance in ACCTDAT (dataset ACCTDATA), and the current-cycle credit and debit totals are reset to zero. COMBTRAN then sorts the interest transactions together with the latest backup of the card-transaction master and reloads TRANSACT. WAITSTEP pauses 36 seconds and OPENFIL gives the files back to the online service, so colleagues and cardholders can sign on again.

If the chain does not run, no monthly interest charge is made, the billing cycle totals are not reset, and the statement job CREASTMT and the online transaction screens show no interest lines for the month. If it runs twice, cardholders are charged twice: nothing in CBACT04C records that an account has already been charged (FR-15, Q-06). Both outcomes are customer-harm cases under the FCA Consumer Duty and affect the periodic statements required by the Consumer Credit Act 1974 (§7, §9).

Business capabilityHow this stream serves it
Monthly interest charge on Clubcard Credit Card accountsPrices each balance by category at the APR pricing group rate and adds the total to the account balance (app/cbl/CBACT04C.cbl:462-470, :350-356).
Card-transaction history and monthly card statementsEach charge becomes a CVTRA05Y transaction (type 01, category 0005, source System, description Int. for a/c + account id) that COMBTRAN merges into the TRANSACT master read by CREASTMT (app/jcl/CREASTMT.JCL:45) and the CT00/CT01 screens (CBACT04C.cbl:482-500; app/jcl/COMBTRAN.jcl:22-48).
Billing-cycle reset at the statement dateSets ACCT-CURR-CYC-CREDIT and ACCT-CURR-CYC-DEBIT to zero when each account is updated (CBACT04C.cbl:353-354).
Pricing governance (Cards Product & Pricing)Rates are reference data, not code: DISCGRP is keyed by account group, transaction type and category, with a mandatory DEFAULT group, so a pricing group can be re-priced without a programme change (CBACT04C.cbl:415-460; app/cpy/CVTRA02Y.cpy:4-9).
Online service availabilityThe CICS card files are closed before the batch update and reopened after it (app/jcl/CLOSEFIL.jcl:26-30, app/jcl/OPENFIL.jcl:26-30). This is the overnight batch outage that operational-resilience impact tolerances must cover.

CardDemo amounts carry no currency. This document reads them as GBP (£) for the Tesco context (A); the source has no currency field or conversion. CardDemo has no Clubcard points logic, and none is described here.

Gating conditions: The chain is defined only in Control-M (app/scheduler/CardDemo.controlm:64-92). CLOSEFIL has no INCOND and posts MONTHLY-InterestCalculation-CLOSEFIL (:65-66). Every later job has one INCOND equal to its predecessor's OUTCOND for the same ODATE (AND_OR="A"); it deletes that condition (SIGN="-") and adds its own (SIGN="+"): INTCALC :70-72, COMBTRAN :76-78, WAITSTEP :82-84, OPENFIL :88-89. OPENFIL adds no condition, so the network ends there. Control-M posts an OUTCOND only when a job ends OK, and the XML has no ON/DO or MAXRC override, so an INTCALC U0999 abend or a non-zero COMBTRAN completion holds the chain with the files still closed. No JCL step has a COND= parameter (app/jcl/INTCALC.jcl:22, app/jcl/COMBTRAN.jcl:22,41), so COMBTRAN STEP10 runs even if SORT ended non-zero. TIMETO="23:00" is the latest submission time, not a completion deadline. No triggers, resources or cross-folder conditions are defined.
Other sources: CA-7 (app/scheduler/CardDemo.ca7) has no INTCALC or COMBTRAN entry. The dashed TRANSACT.BKUP(0) node is shown because COMBTRAN's SORTIN reads it, not because this folder schedules TRANBKP (Q-04). The developer script scripts/run_interest_calc.sh submits a different order (§3, Q-04).

5. Functional requirements

IDRequirementSourceAcceptance criteria
FR-01Before any batch update the five CICS files TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC are closed in region CICSAWSA, and they are reopened after the chain. INTCALC is released only after the close, and OPENFIL only after WAITSTEP.app/jcl/CLOSEFIL.jcl:26-30; app/jcl/OPENFIL.jcl:26-30; app/scheduler/CardDemo.controlm:66,70,88While INTCALC and COMBTRAN run, no online transaction can update those files. The target either provides the same exclusive access or documents why it is not needed. After the chain all five files are open.
FR-02INTCALC is one step, STEP15, running CBACT04C with a 10-character run-date PARM ('2022071800'). The programme does not parse or validate the PARM as a date; it uses it only as the prefix of the generated transaction ids.app/jcl/INTCALC.jcl:22; app/cbl/CBACT04C.cbl:176-178,476-480With PARM 2022071800 the run produces transaction ids 2022071800000001, 2022071800000002, …. The target rejects a run date that is not exactly 10 characters.
FR-03Open modes: TCATBALF, XREFFILE and DISCGRP INPUT; ACCTFILE I-O; TRANSACT (SYSTRAN) OUTPUT. Any open status other than 00 abends before any record is processed.CBACT04C.cbl:236,254,272,291,309; 0000-TCATBALF-OPEN … 0400-TRANFILE-OPENWith an input dataset missing or still held by CICS, the job abends U0999 with the matching ERROR OPENING … message; no account changes and no SYSTRAN generation is kept.
FR-04Balances are processed in TCATBALF key order (account id, type code, category code) by sequential read. Status 10 ends the run normally; any other non-00 status abends.CBACT04C.cbl:28-32,61-67,325-348Given balances for accounts 00000000011 and 00000000010, account 10's transactions are generated first. An I/O error logs ERROR READING TRANSACTION CATEGORY FILE and abends.
FR-05When the account id changes, the credit card account (by ACCT-ID) and the card-to-account link (by alternate key XREF-ACCT-ID) are read once and reused for all that account's categories, and the account's interest total is reset to zero.CBACT04C.cbl:194-205,372-376,393-398An account with three category balances causes exactly one ACCTFILE read and one XREFFILE read; all three transactions carry the same TRAN-CARD-NUM.
FR-06The rate for a balance comes from the DISCGRP (APR pricing group) record keyed by (ACCT-GROUP-ID, balance type code, balance category code).CBACT04C.cbl:210-213,415-420; app/cpy/CVTRA02Y.cpy:5-8For group GOLD, type 01, category 0001, the rate stored under that key is used, not the DEFAULT rate, when the row exists.
FR-07If the group-specific DISCGRP record is missing (status 23), the programme logs DISCLOSURE GROUP RECORD MISSING and TRY WITH DEFAULT GROUP CODE, then retries once with group id DEFAULT and the same type and category. If DEFAULT is also missing it abends with ERROR READING DEFAULT DISCLOSURE GROUP.CBACT04C.cbl:416-439,443-460Remove the GOLD 01 0001 rate and the run uses DEFAULT 01 0001. Remove both and the job abends at that balance.
FR-08A rate of zero produces no interest transaction and leaves the account total unchanged. No fees are charged: 1400-COMPUTE-FEES is an empty stub (* To be implemented).CBACT04C.cbl:214-217,518-520A balance whose resolved rate is 0.00 produces no SYSTRAN record. The migrated job produces no fee transactions.
FR-09Monthly interest per category = TRAN-CAT-BAL × DIS-INT-RATE ÷ 1200, stored in PIC S9(09)V99 without ROUNDED, so it is truncated toward zero to two decimals. A non-zero rate on a zero balance still writes a 0.00 transaction.CBACT04C.cbl:168,214,462-468Balance 1000.00 at rate 18.50 gives 15.41 (not 15.42); −1000.00 gives −15.41; 0.00 gives one 0.00 transaction.
FR-10The account's total interest is the sum of the per-category amounts after truncation.CBACT04C.cbl:467Three categories that each compute 0.333… produce three 0.33 transactions and a balance increase of 0.99, not 1.00.
FR-11Each charge is one CVTRA05Y transaction: TRAN-ID = PARM + 6-digit sequence (starts at 000001, one per transaction across the whole run); TRAN-TYPE-CD '01'; TRAN-CAT-CD = literal '05' moved into PIC 9(04), so stored as 0005; TRAN-SOURCE System; TRAN-DESC = Int. for a/c + 11-digit account id; amount = truncated interest; merchant id 0; merchant name, city, postcode blank; card number = the account's x-ref card number.CBACT04C.cbl:173,473-495; app/cpy/CVTRA05Y.cpy:5-15The second transaction of the run, whichever account it belongs to, has id <PARM>000002. A record for account 00000000010 has TRAN-DESC starting Int. for a/c 00000000010 and category 0005.
FR-12TRAN-ORIG-TS and TRAN-PROC-TS are both the same current clock time in DB2 format YYYY-MM-DD-HH.MM.SS.hh0000 (26 characters).CBACT04C.cbl:496-498,613-626Generated records match ^\d{4}-\d{2}-\d{2}-\d{2}\.\d{2}\.\d{2}\.\d{2}0000$, and ORIG equals PROC.
FR-13Interest transactions go to INTCALC's sequential TRANSACT DD, a new SYSTRAN(+1) generation of fixed 350-byte records in generation order. INTCALC never writes the TRANSACT master. A write status other than 00 abends.app/jcl/INTCALC.jcl:37-41; CBACT04C.cbl:53-56,500-514After INTCALC the master record count is unchanged; the new SYSTRAN generation has one record per priced category, LRECL 350.
FR-14When the account id changes (not on the first account) the previous account is rewritten: ACCT-CURR-BAL += total interest, ACCT-CURR-CYC-CREDIT = 0, ACCT-CURR-CYC-DEBIT = 0. A rewrite status other than 00 abends.CBACT04C.cbl:194-199,350-369An account with balance 500.00, cycle credit 120.00, cycle debit 80.00 and total interest 7.70 reads back 507.70 / 0.00 / 0.00 once the next account is reached.
FR-15Preserved quirk: the last account in TCATBALF key order is never updated, although its transactions are still written. The end-of-file branch at :219-220 is unreachable because PERFORM UNTIL END-OF-FILE = 'Y' tests before each pass, so the outer IF END-OF-FILE = 'N' is always true. Nothing marks a balance as already charged, so a rerun charges again.CBACT04C.cbl:188-191,219-221Parity test with two accounts: only the first has its balance and cycle totals changed; the second has SYSTRAN records but an unchanged ACCTDATA record. Running INTCALC twice doubles the first account's increase. Whether to keep this is Q-06.
FR-16A missing account or x-ref record for a balance abends the run after logging ACCOUNT NOT FOUND: + id and then ERROR READING ACCOUNT FILE or ERROR READING XREF FILE. There is no reject file and no skip.CBACT04C.cbl:372-391,393-413A TCATBALF row for an account not in ACCTDATA stops the job; earlier accounts stay updated in the legacy system (no backout).
FR-17COMBTRAN STEP05R sorts TRANSACT.BKUP(0) then SYSTRAN(0) ascending on the 16-byte character field at position 1 (TRAN-ID) into a new TRANSACT.COMBINED(+1) with the SORTIN DCB. Duplicates are kept (no SUM FIELDS).app/jcl/COMBTRAN.jcl:22-37Output count = BKUP count + SYSTRAN count, in ascending TRAN-ID order, LRECL 350.
FR-18COMBTRAN STEP10 loads every COMBINED record into the TRANSACT KSDS with REPRO INFILE(TRANSACT) OUTFILE(TRANVSAM), with no REPLACE and no COND=, so it runs even if SORT ended non-zero.app/jcl/COMBTRAN.jcl:41-48From an empty master, after STEP10 the master holds exactly the COMBINED records keyed by TRAN-ID. 6.3 Restart / checkpoint semantics

No job in the chain takes a checkpoint or has a commit interval. CBACT04C rewrites each account as soon as the next account starts (app/cbl/CBACT04C.cbl:194-199,350-356) and keeps no record of which accounts are done, so the run is not idempotent. A cold rerun after a partial or complete INTCALC charges interest again on every account already updated. The only safe recovery is: restore ACCTDATA (and TRANSACT, if COMBTRAN ran) from the pre-run backup, then rerun from INTCALC with the same PARM so that transaction ids are reproduced. The source has no backup or backout job for ACCTDATA in this folder (Q-06). COMBTRAN can be rerun on its own only against an empty or freshly redefined TRANSACT KSDS, because REPRO has no REPLACE (Q-05). CLOSEFIL, WAITSTEP and OPENFIL are stateless. Control-M allows up to five reruns (MAXRERUN="5") and keeps an unrun order for seven days (MAXWAIT="7") (app/scheduler/CardDemo.controlm:65). The target commits one account group per chunk (InterestCalculationJobConfiguration.java:58,125), so a failed target run keeps the accounts committed before the failure. Restart rules there are still to be agreed (Q-06).
