1. Business purpose

For the Tesco Bank Clubcard Credit Card platform, TransactionReporting gives colleagues two printed views of posted card transactions (purchases, cash, payments and refunds held in TRANSACT). The Daily Transaction Report (programme CBTRN03C) lists every card transaction whose processing date falls in a requested period. It groups them by Clubcard Credit Card (PAN), resolves each card to its credit card account through the card-to-account-to-customer link (CARDXREF), and shows account, page and grand totals. A colleague requests the report from CICS screen CR00 (program CORPT00C, app/csd/CARDDEMO.CSD:409-410). The program builds a 17-card JCL deck for job TRNRPT00 (app/cbl/CORPT00C.cbl:81-125) and writes it to the extra-partition transient data queue JOBS, whose DD INREADER feeds the JES internal reader (app/csd/CARDDEMO.CSD:499-503).

The category-balance print (PRTCATBL) unloads TCATBALF, the balance per credit card account, transaction type and category, which daily posting maintains. It writes a sorted, edited listing (app/jcl/PRTCATBL.jcl:21-63). In Tesco Bank terms this is the balance-by-category view (for example purchase, cash or balance-transfer balances; the category meaning is an assumption, Q-24) that later drives the monthly interest charge. CA-7 runs the print inside a CLOSEFIL → PRTCATBL → WAITSTEP → OPENFIL bracket, which takes five CICS files offline while it runs (app/scheduler/CardDemo.ca7:529-571).

If the chain does not run, there is no transaction report for the requested period. The colleague still sees ... report submitted for printing ..., because the screen does not wait for the job. The overnight balance-by-category listing is also missing. A failure between CLOSEFIL and OPENFIL leaves TRANSACT, CCXREF, ACCTDAT, CXACAIX and USRSEC closed to CICS. Colleague sign-on (USRSEC) and the card account and transaction screens stay unavailable until OPENFIL is run by hand (app/jcl/OPENFIL.jcl:26-30). This is the chain's real operational-resilience exposure.

Colleague self-service (online to batch)Because the job is handed to the internal reader, TRANREPT needs no scheduler entry; the JCL and its date parameters are generated at request time (app/cbl/CORPT00C.cbl:462-510).

Gating conditions: Trigger A. No scheduler releases TRANREPT: TRANREPT and TRNRPT00 appear in neither CardDemo.ca7 nor CardDemo.controlm. The job exists only after CORPT00C has validated the request, the colleague has typed Y/y in CONFIRM, and every card up to and including /*EOF has been written to TDQ JOBS with DFHRESP(NORMAL) (app/cbl/CORPT00C.cbl:464-508, :525-535). Every error path ends the task, because SEND-TRNRPT-SCREEN finishes with GO TO RETURN-TO-CICS (:556-580). No step inside the job has COND= (app/proc/TRANREPT.prc:21,35,57). The only gate between steps is allocation of the (+1) generation the previous step should have created. Trigger B. CA-7 uses completion triggers only, each with QTM=0100 LEADTM=0000 SUBMTM=0000. OPENFIL of SCHID=030 triggers CLOSEFIL SCHID=031 (CardDemo.ca7:529-532). CLOSEFIL triggers PRTCATBL SCHID=031 (:534-537). PRTCATBL triggers WAITSTEP SCHID=031 (:563-564). WAITSTEP triggers OPENFIL SCHID=031 (:566-569). The listing also has a second WAITSTEP block, after TRANCATG SCHID=031, that triggers CLOSEFIL SCHID=030 (:298-303). CA-7 lists triggers per job name, and the listing does not show which triggering SCHID each one applies to, so completing WAITSTEP under 031 may release both successors (dashed edge, Q-03). There are no CA-7 requirements and no Control-M IN/OUT conditions for this network: PRTCATBL, TCATBALF and TRANREPT have zero matches in CardDemo.controlm. PRTCATBL's three steps have no COND= (app/jcl/PRTCATBL.jcl:21,29,43). Scheduler disagreement (not merged into one chain): CA-7 SCHID=030 daily is CLOSEFIL → CBPAUP0J → POSTTRAN → WAITSTEP → OPENFIL, with no TRANBKP (CardDemo.ca7:18-124). Control-M DAILY-TransactionBackup is CLOSEFIL → TRANBKP → WAITSTEP → OPENFIL via OUTCOND/INCOND pairs, with no POSTTRAN (CardDemo.controlm:3-25). Its TIMETO="23:00" is the latest submission time, not a completion deadline (:4). This FRD documents each source as written (Q-01).

6.3 Restart / checkpoint semantics

The chain has no checkpoints or commit points. CBTRN03C makes a single pass over a sequential extract and has no restart key (app/cbl/CBTRN03C.cbl:170-206), so the unit of restart is the whole job. Every output is either a new GDG generation (DISP=(NEW,CATLG,DELETE), app/proc/TRANREPT.prc:27,49,74; app/jcl/PRTCATBL.jcl:35) or a dataset that is deleted first (TCATBALF.REPT, app/jcl/PRTCATBL.jcl:21-25). A cold rerun is therefore always safe and needs no backout; it simply adds another generation. CORPT00C fixes the job name as TRNRPT00 (app/cbl/CORPT00C.cbl:83-84). Whether two concurrent colleague requests run side by side or one after the other depends on the JES duplicate-job-name setting, which is not in the repo (Q-22). In trigger B, if PRTCATBL or WAITSTEP fails, the five CICS files stay closed until Tesco Technology — Mainframe Platform submits OPENFIL by hand (app/jcl/OPENFIL.jcl:26-30). CA-7 does not release OPENFIL because the trigger chain is broken (app/scheduler/CardDemo.ca7:563-569).
