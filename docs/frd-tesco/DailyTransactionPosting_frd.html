1. Business purpose

DailyTransactionPosting is the overnight batch network that turns the day’s captured Clubcard Credit Card transactions — purchases, cash, payments and refunds — into posted card-transaction history and up-to-date credit card account balances. In CARDDEMO terms it reads the daily transaction file DALYTRAN, checks each card transaction against the card-to-account-to-customer link (CCXREF / CARDXREF) and the credit card account (ACCTDAT / ACCTDATA), and then either posts it or rejects it.

The five jobs run in this order. CLOSEFIL takes five files away from the online CICS region so that batch may update them (app/jcl/CLOSEFIL.jcl:22-30). CBPAUP0J runs the IMS BMP CBPAUP0C, which deletes pending card authorisations older than the expiry window from the DBPAUTP0 database (app/app-authorization-ims-db2-mq/jcl/CBPAUP0J.jcl:24-25). POSTTRAN runs CBTRN02C (app/jcl/POSTTRAN.jcl:23): each valid transaction is written to the card transaction master TRANSACT, added to the account’s current balance and cycle credit / debit totals, and added to the account’s balance by category (TCATBALF); each invalid one is written with a reason code to a new generation of the reject file DALYREJS (app/cbl/CBTRN02C.cbl:193-234). WAITSTEP pauses for 36 seconds (app/jcl/WAITSTEP.jcl:26) and OPENFIL hands the files back to CICS (app/jcl/OPENFIL.jcl:22-30).

If the network does not run, the cardholder’s day of card activity is not posted: online transaction screens show stale history, the account’s current balance and cycle totals are wrong for the monthly interest charge (INTCALC) and the monthly card statement (CREASTMT) that read them, and expired authorisations keep holding open-to-buy in the pending-authorisation database. If it stops after CLOSEFIL and before OPENFIL, the five CICS files stay closed and every online function that needs them — colleague sign-on included, through USRSEC — fails until someone runs OPENFIL. Amounts in the source carry no currency; this document reads them as pounds sterling for Tesco Bank (A-06). Clubcard points are not in CardDemo and are not part of this chain.

Business capabilityHow this stream serves it

Gating conditions: CA-7 releases each successor on completion of its predecessor through TRIGGERED JOBS ... SCHID=030 QTM=0100 LEADTM=0000 (CardDemo.ca7:43, 70, 97, 124). None of the five LJOB blocks lists a requirement, calendar or condition-code test, and the OPENFIL block shows N -- COMP TRIGGERS OTHER JOBS with no TRIGGERED JOBS section (CardDemo.ca7:126-148), so OPENFIL ends this network. No JCL member in the chain has a COND= parameter and each has a single step, so a non-zero RC does not stop the chain on its own: POSTTRAN ending RC 4 because of rejects (CBTRN02C.cbl:229-231) still releases WAITSTEP. Whether CA-7 withholds a trigger after CBPAUP0C’s RC 16 (CBPAUP0C.cbl:380-383) or a CBTRN02C U0999 abend (CBTRN02C.cbl:707-711) is not stated in the listing (Q-03). Scheduler mismatch: the Control-M folder DAILY-TransactionBackup is CLOSEFIL → TRANBKP → WAITSTEP → OPENFIL, gated by IN / OUT conditions (CardDemo.controlm:4-24; DAYS="ALL", MAXRERUN="5", and TIMETO="23:00", which is the latest submission time, not a completion deadline). It has no CBPAUP0J or POSTTRAN, and CardDemo.ca7 never mentions TRANBKP. This document records the CA-7 network as written and does not assert a combined chain (Q-01). The developer script scripts/run_posting.sh:12-34 submits a third ordering (Q-21).

FR-05A detail is expired when CURRENT-YYDDD − (99999 − PA-AUTH-DATE-9C) ≥ expiry days. An expired detail with response code '00' reduces the in-memory approved count by 1 and approved amount by PA-APPROVED-AMT; any other code reduces the declined count by 1 and declined amount by PA-TRANSACTION-AMT; the detail is then deleted (DLET).CBPAUP0C / 4000-CHECK-IF-EXPIRED, 5000-DELETE-AUTH-DTL (CBPAUP0C.cbl:277-325)With expiry 5 and details dated today, today−4 and today−5 (YYDDD), only the today−5 detail is deleted and its counters are subtracted. The comparison is plain YYDDD arithmetic, not calendar dates (Q-10).
FR-06After its details, a root is deleted when PA-APPROVED-AUTH-CNT ≤ 0. The source tests the approved count twice and never the declined count, and a kept root is never rewritten (no REPL), so the adjusted counters are not saved.CBPAUP0C.cbl:156-158, 328-349A root with approved count 0 and declined count 3 is deleted; a root with approved count 1 is kept with its stored counters unchanged (Q-11).

The checkpoint id is the constant RMAD0000 and no XRST is issued.CBPAUP0C / 9000-TAKE-CHECKPOINT (CBPAUP0C.cbl:75-77, 160-164, 169, 352-374)The final CHKP is always taken; a restart reprocesses from the first root. The interval actually used must be confirmed by a compiled test before the target picks a commit interval (Q-12).
FR-08Any DL/I status other than blank (or GB on GN, GE / GB on GNP) makes CBPAUP0C display the failing call and status, display CBPAUP0C ABENDING ..., set RETURN-CODE 16 and GOBACK. A clean run prints the four totals: summaries read, summaries deleted, details read, details deleted.CBPAUP0C.cbl:228-241, 259-271, 315-321, 340-346, 358-370, 173-176, 377-383A forced DLET failure ends the job RC 16 with no abend code; a clean run ends RC 0 and the four counters match the fixture.
FR-09CBTRN02C opens its six files in this order and mode: DALYTRAN INPUT, TRANFILE OUTPUT, XREFFILE INPUT, DALYREJS OUTPUT, ACCTFILE I-O, TCATBALF I-O. TRANFILE OUTPUT means posting loads the transaction master rather than appending. Any open status other than '00' abends.CBTRN02C.cbl:195-200, 236-343After a run the transaction master holds only this run’s transactions; a missing input ends with ERROR OPENING ..., FILE STATUS IS: NNNN and abend U0999.
FR-10Daily records are processed in file order in one pass. Status '10' ends the loop; any other non-'00' read status abends. Each record adds 1 to TRANSACTIONS PROCESSED, resets the reason to 0, then is either posted (reason 0) or rejected.CBTRN02C / 1000-DALYTRAN-GET-NEXT (CBTRN02C.cbl:202-219, 345-369)For N input records, PROCESSED = N and posted + rejected = N; an empty file gives counts 0 and RC 0.
FR-11A record whose DALYTRAN-CARD-NUM is not in CARDXREF is rejected with reason 0100, text INVALID CARD NUMBER FOUND; the account checks are skipped.CBTRN02C / 1500-A-LOOKUP-XREF (CBTRN02C.cbl:370-392)Unknown card → one reject with trailer starting 0100INVALID CARD NUMBER FOUND; no account or category balance change.

6.3 Restart / checkpoint semantics

POSTTRAN / CBTRN02C has no checkpoint, commit interval or restart key; it is one pass over DALYTRAN (CBTRN02C.cbl:202-219). TRANFILE is OPEN OUTPUT (:256), so a cold rerun reloads the transaction master, and DALYREJS(+1) DISP=(NEW,CATLG,DELETE) (POSTTRAN.jcl:34) gives a fresh reject generation. ACCTFILE REWRITEs (:554) and TCATBALF WRITE / REWRITEs (:510, :528) are made in place and are not reversed on abend, so a rerun after a partial run counts every already-posted transaction twice against the cardholder’s balance. The legacy recovery is therefore: restore ACCTDATA and TCATBALF, make TRANSACT reusable, rerun POSTTRAN from the top.

CBPAUP0J / CBPAUP0C takes EXEC DLI CHKP ID(WK-CHKPT-ID) when the per-interval root count exceeds P-CHKP-FREQ and once at end of run (CBPAUP0C.cbl:160-164, 169, 355), always with id RMAD0000 (:75-77) and no XRST. A restart reprocesses from the first root; work committed at earlier checkpoints is already applied and is not repeated.

CLOSEFIL, WAITSTEP, OPENFIL are stateless and can be rerun at any time. If the chain stops between CLOSEFIL and OPENFIL, Batch Operations runs OPENFIL by hand to restore online service.

NFR-08Accuracy / customer outcomesPosted balances feed the monthly interest charge and the monthly card statement (CCA 1974 s.78(4) periodic statements).
